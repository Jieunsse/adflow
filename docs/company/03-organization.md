# AdFlow 회사 설계 3. 조직과 채용

작성일: 2026-11-11 · 상태: 초안 (확정 전) · 기준 문서: `01-business-structure.md`, `02-finance.md`

## 1. 시작 조직과 확장 방식

**대표와 퍼포먼스 마케터 1명으로 시작합니다 (확정).** 이후 정해 둔 기준에 닿을 때마다 한 명씩 뽑습니다. 이전 초안의 "직원 2명으로 시작"은 대체됨입니다.

일은 사람이 아니라 기능별로 나눕니다. 사람이 늘면 앞사람이 임시로 맡던 일을 새 사람에게 넘깁니다.

| 자리 | 맡는 일 | 들어오기 전까지 임시로 맡는 사람 | 상태 |
|---|---|---|---|
| 대표 | AdFlow 개발, 대행·납품 영업과 계약, 재무, 채용 | — | 확정 (대표가 개발자) |
| 퍼포먼스 마케터 | 대행 계정 운영. 고객 시작 준비, 월간 실험 계획, 게재 승인, 판정 확인, 배운 것 확정, 월간 리포트 설명 | — (설립 때 뽑음) | 권장 |
| 콘텐츠 마케터 | 모든 대행 고객의 소재 검수와 수정, 브랜드 규칙(SOP) 정리, 구독 고객 지원과 도움말 작성 | 소재 검수는 퍼포먼스 마케터, 구독 고객 지원은 대표 | 권장 |

**두 번째 자리를 퍼포먼스 마케터가 아니라 콘텐츠 마케터로 둔 이유 (권장)**
- AdFlow가 가설, 판정, 기록을 맡습니다. 그래서 계정 운영의 손은 줄어듭니다.
- AdFlow가 줄이지 못하는 것은 소재의 질입니다. 고객이 가장 먼저 보는 것도 소재입니다. AI가 만든 소재를 사람이 검수해야 브랜드 톤이 지켜집니다.
- 구독을 열면 고객 지원을 맡을 사람이 필요합니다. 대표가 오래 맡으면 개발이 멈춥니다.

**이 구조의 위험 (가설).** 퍼포먼스 마케터 한 명이 대행 계정을 몇 곳까지 운영할 수 있는지 모릅니다. 재무 문서의 기본 시나리오는 대행 고객 16곳에 닿습니다. 이때 운영하는 사람이 한 명뿐이면 감당하기 어렵습니다. 그래서 세 번째 채용 기준을 고객 수로 정해 둡니다 (4절).

## 2. 한 대행 고객을 나눠 맡는 방식

콘텐츠 마케터가 들어오기 전에는 콘텐츠 마케터 칸의 일을 퍼포먼스 마케터가 맡습니다.

| 단계 | 퍼포먼스 마케터 | 콘텐츠 마케터 | 대표 | AdFlow가 하는 일 |
|---|---|---|---|---|
| 계약 | | | 계약, 첫 달 50% 청구 | |
| 시작 준비 (1주 안) | 광고 계정 파트너 공유 받기, 과거 광고 가져오기 | 브랜드 규칙 등록 | | 과거 광고 불러오기, 첫 실험 후보 제안 |
| 월간 계획 | 그달 실험 계획을 만들고 고객 승인 받기 | | | 가설 초안, 오늘의 결정 |
| 매주 실험 | 게재 승인, 판정 확인, 배운 것 확정 | 소재 검수와 수정 | | 소재 생성, 브랜드 규칙 검사, 판정, 기록 초안 |
| 월간 리포트 | 고객에게 리포트 설명 (30분 통화) | | | 성과 → 이유 → 다음 할 일 리포트 |
| 재계약 (3개월째) | 3개월 동안 배운 것 정리 | | 재계약 | 배운 것 목록 내보내기 |

**고객 한 곳에 쓰는 시간 목표 (가설)**
- 퍼포먼스 마케터: 주 2시간
- 콘텐츠 마케터: 주 1시간
- 이 시간을 넘으면 AdFlow에서 손이 가장 많이 가는 단계부터 고칩니다. 그래서 직원이 단계별 작업 시간을 기록해야 합니다.

## 3. 직원이 AdFlow의 첫 사용자다

직원이 매일 AdFlow로 일합니다. 그래서 제품 기획을 아래처럼 바꿨습니다 (2026-11-11, 기획서 6.2절과 정책서 5·27·28절에 반영).

| 바뀌는 것 | 이유 | 상태 |
|---|---|---|
| "여러 브랜드 관리"를 1차 출시 필수 기능으로 올립니다 | 직원 한 명이 여러 고객을 동시에 맡습니다 | 확정 |
| "대행 담당자" 역할은 만들지 않고, 고객에게 줄 "고객" 역할을 새로 만듭니다 | 우리 회사 공간에 고객사 브랜드를 여러 개 두므로 직원은 지금 역할로 충분합니다. 고객 역할은 보기와 월간 계획 승인만 할 수 있습니다 | 확정 (2026-11-11) |
| 대행 고객은 월간 계획 승인, 성과 리포트, 배운 것 기록, 진행 중인 실험 목록(읽기만)을 봅니다 | 진행 상황을 직접 볼 수 있어야 문의 연락이 줄어듭니다. 소재 만들기, 브랜드 규칙, 설정은 보여 주지 않습니다 | 확정 (2026-11-11) |
| 직원별 작업 시간 기록 | 마케터 1명당 고객 수를 재야 합니다 | 권장 |
| 고객사 관리에 영업 단계를 덧붙입니다 | 영업 관리를 따로 사거나 만들지 않고 AdFlow 안에서 합니다 (아래 3-1) | 확정 |

### 3-1. 영업 관리도 AdFlow 안에서 합니다

**별도 CRM 도구를 쓰지 않습니다 (확정).** AdFlow의 고객사(브랜드) 관리에 계약 전 단계를 덧붙입니다.

**이렇게 하는 이유**
- AdFlow에는 이미 고객사 정보가 있습니다. 여기에 계약 전 상태만 붙이면 영업 관리가 됩니다.
- 상담하던 회사가 계약하면 같은 기록이 그대로 대행 계정으로 이어집니다. 다른 도구에서 옮겨 올 필요가 없습니다.
- "기록은 고객 것이고 끊기지 않는다"는 회사 약속(사업 구조 문서 2절)과 맞습니다.
- 별도 CRM 제품을 만들면 대표의 AdFlow 개발 시간이 줄어듭니다. 그래서 따로 만들지 않고 덧붙이는 정도로 둡니다.

**1차 출시에 넣는 것 (권장, 정책서 27절)**

| 항목 | 내용 |
|---|---|
| 고객사 상태 | 문의 → 상담 → 제안 → 계약 → 재계약 대기 → 종료 |
| 담당 직원 | 이 고객사를 누가 맡고 있는지 |
| 다음 할 일과 날짜 | "목요일에 제안서 보내기" 같은 한 줄 |
| 재계약일 | 3개월 계약이 끝나기 2주 전에 담당 직원과 대표에게 알립니다 |
| 상담 메모 | 통화와 미팅 내용을 시간순으로 남깁니다 |

**1차 출시에 넣지 않는 것 (권장)**
- 메일과 캘린더 연동
- 영업 단계별 통계와 그래프
- 견적서와 계약서 자동 생성

위 기능은 대행 고객이 10곳을 넘고 실제로 불편해질 때 하나씩 검토합니다.

**구독 고객은 여기에 넣지 않습니다 (권장).** 구독은 고객이 스스로 가입합니다. 상담과 제안 단계가 없으므로 영업 단계를 쓰지 않습니다.

## 4. 채용

| 순서 | 자리 | 언제 | 무엇을 보고 뽑나 | 상태 |
|---|---|---|---|---|
| 1 | 퍼포먼스 마케터 | 설립 때 | Meta 광고 운영 1~3년. 숫자로 설명하는 사람. 도구를 바꾸는 데 거부감이 없는 사람 | 권장 |
| 2 | 콘텐츠 마케터 | 대행 고객 6곳이 된 다음 달 (재무 문서 3절) | 짧은 영상과 카피 작업 경험. 브랜드 톤을 글로 정리할 수 있는 사람 | 권장 |
| 3 | 퍼포먼스 마케터 | 대행 고객 16곳에 닿았는데 새 대행 문의가 기다리고 있을 때. 이 사람의 인건비는 17번째 고객부터 내는 매출로 냅니다. 그래서 재무 문서의 12개월 예상에는 넣지 않았습니다 | 1번과 같음 | 권장 |
| 4 | 개발자 | 구독 매출 비중 20% 이상, 또는 납품 2건 이상 | 대표의 개발 시간이 영업에 밀릴 때 | 권장 |

- 첫 채용은 정규직으로 권장합니다. 대행 고객이 담당자가 자주 바뀌는 것을 가장 싫어하기 때문입니다.
- 대행 노하우가 AdFlow 기록에 남으므로, 직원이 바뀌어도 고객 기록은 회사에 남습니다. 이는 우리가 고객에게 하는 약속과 같은 이야기입니다.

## 5. 정해야 할 것

| 항목 | 정하는 방법 |
|---|---|
| 퍼포먼스 마케터 1명이 맡을 수 있는 고객 수 | 첫 고객 2~4곳에서 작업 시간을 잽니다 |
