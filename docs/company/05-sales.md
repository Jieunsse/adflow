# AdFlow 회사 설계 5. 영업

작성일: 2026-11-11 · 상태: 초안 (확정 전) · 기준 문서: `01-business-structure.md`, `02-finance.md`, `03-organization.md`, `04-operations.md`

이 문서는 고객을 어디서 데려오고, 어떻게 계약까지 이어 가는지 정합니다.
영업 기록은 별도 도구 없이 AdFlow 고객사 관리에 남깁니다 (조직 문서 3-1).

## 1. 부문별 영업 방식

| 부문 | 영업 방식 | 맡는 사람 | 상태 |
|---|---|---|---|
| 대행 | 고객이 먼저 문의하게 만듭니다. 우리 광고 실험 공개와 Meta 광고로 문의를 모읍니다 | 대표 | 확정 |
| 구독 | 고객이 스스로 가입합니다. 상담과 제안 단계가 없습니다 | — | 확정 (조직 문서 3-1) |
| 납품 | 먼저 나서서 팔지 않습니다. 요청이 올 때만 받습니다 | 대표 | 확정 (사업 구조 문서 5절) |

- **직접 연락하는 영업은 하지 않습니다 (권장).** 자사몰에 메일이나 DM을 보내는 일은 응답률이 낮습니다. 개발도 맡은 대표의 시간이 가장 많이 빠지는 방식입니다.
- **외주 플랫폼에는 올리지 않습니다 (권장).** 수수료가 있고 가격 비교가 심합니다. "기록이 남는 대행"이라는 차이를 설명하기도 어렵습니다.

## 2. 대행 고객이 계약까지 오는 길

| 단계 | 고객이 하는 일 | 우리가 하는 일 | AdFlow 고객사 상태 | 상태 |
|---|---|---|---|---|
| 1. 알게 됨 | 실험 공개 글이나 Meta 광고를 봅니다 | 매주 실험 공개, Meta 광고 운영 | — | 확정 |
| 2. 문의 | 문의 양식을 채우거나 카카오톡 채널로 연락합니다 | 1영업일 안에 받는 기준(4절)을 확인합니다 | 문의 | 권장 |
| 3. 무료 진단 | 광고 계정을 읽기 권한으로 공유합니다 | 지난 광고를 불러와 진단서를 만듭니다 (5절) | 상담 | 확정 |
| 4. 상담 | 30분 통화로 진단서 설명을 듣습니다 | 첫 달 실험 계획 초안을 함께 보여 줍니다 | 상담 | 권장 |
| 5. 제안 | 제안서를 받습니다 | 상담 후 2영업일 안에 제안서를 보냅니다 | 제안 | 권장 |
| 6. 계약 | 서명하고 첫 달 50%를 냅니다 | 고객 시작 준비를 합니다 (운영 문서 2절) | 계약 | 확정 |

- 제안 후 2주 동안 답이 없으면 한 번만 다시 연락합니다. 그래도 답이 없으면 "종료"로 바꾸고 이유를 적습니다 (권장).
- 받는 기준에 못 미치는 문의는 진단하지 않고 개인 구독을 안내합니다 (4절).

## 3. 고객을 데려오는 방법

### 3.1 우리 광고 실험 공개

다른 대행사는 결과만 보여 줍니다. 우리는 실험 과정과 이긴 이유를 보여 줍니다. 이 차이를 가장 잘 보여 주는 방법입니다.

| 규칙 | 상태 |
|---|---|
| 매주 1편 이상 공개합니다. 내용은 "가설, 바꾼 요소, 두 소재, 결과, 배운 것"입니다 | 권장 |
| 블로그에 원문을 쓰고, 스레드와 인스타그램에는 짧게 나눠 올립니다 | 권장 |
| 고객 이름과 제품 이름은 빼고 "뷰티 자사몰 A"처럼 씁니다 | 확정 |
| 광고비와 매출 금액은 공개하지 않습니다. 클릭률, 3초 시청률 같은 비율만 공개합니다 | 권장 |
| 계약서에 "익명 사례 공개 동의" 조항을 넣습니다. 동의하지 않은 고객의 실험은 공개하지 않습니다 | 권장 (법·행정 단계에서 문구 확인) |
| 고객이 생기기 전에는 우리 Meta 광고의 실험을 공개합니다 (3.2) | 권장 |

- 실험 기록은 이미 AdFlow에 사람이 읽을 수 있는 문장으로 남습니다. 그래서 공개 글 초안은 기록에서 바로 만들 수 있습니다. 쓰는 사람은 콘텐츠 마케터이고, 채용 전에는 대표입니다 (권장).

### 3.2 Meta 광고

| 규칙 | 상태 |
|---|---|
| 우리 대행 상품 광고를 AdFlow로 직접 운영합니다 | 확정 |
| 예산은 월 50만 원입니다 (재무 문서 1절의 영업·마케팅 비용) | 권장 |
| 광고의 목적지는 무료 진단 신청 페이지입니다 | 권장 |
| 이 광고의 실험도 3.1처럼 공개합니다 | 권장 |

- 우리 광고가 AdFlow로 잘 되면 그 자체가 가장 좋은 사례입니다. 잘 안 되면 고객보다 먼저 우리가 문제를 알게 됩니다.

## 4. 대행을 받는 기준

| 조건 | 이유 | 상태 |
|---|---|---|
| 자사몰이 있습니다 | 광고 목적지와 상품 정보가 있어야 소재를 만들 수 있습니다 | 확정 |
| Meta 광고 계정이 있습니다 | 파트너 공유로 운영합니다 (운영 문서 2절) | 확정 |
| 월 광고비를 100만 원 이상 쓸 수 있습니다 | 이보다 적으면 판정할 데이터가 모이지 않습니다. 그러면 운영비가 광고비보다 비싸게 보여 재계약이 어렵습니다 | 확정 |
| 제품 사진과 영상을 줄 수 있습니다 | 우리는 촬영하지 않습니다 (운영 문서 5절) | 확정 |

- **업종은 제한하지 않습니다 (확정).** 자사몰이면 업종을 가리지 않고 받습니다. 다만 법이나 Meta가 광고를 강하게 막는 업종(정책서 23.2의 받지 않는 업종)은 받지 않습니다 (법·행정 문서 5절).
- 기준에 못 미치면 개인 구독을 안내합니다. 광고비가 늘면 대행으로 다시 오도록 고객사 기록을 "종료"가 아니라 "문의" 상태로 남깁니다 (권장).

## 5. 무료 광고 계정 진단

| 규칙 | 상태 |
|---|---|
| 받는 기준(4절)을 채운 문의에만 진단합니다 | 확정 |
| 고객은 광고 계정을 읽기 권한으로 우리에게 공유합니다. 진단이 끝나면 공유를 해제해도 된다고 안내합니다 | 권장 (외부 검증) |
| 진단서는 한 장입니다. 내용은 "지난 광고에서 이긴 것과 진 것, 그 차이로 짐작되는 이유, 첫 달에 해 볼 실험 3개"입니다 | 확정 |
| 지난 광고는 여러 요소를 한꺼번에 바꾼 경우가 많습니다. 그래서 진단서의 이유는 "짐작"으로 표시합니다 | 확정 (기획서 6.2의 과거 기록 원칙) |
| 진단 한 건에 직원 시간은 1시간을 넘기지 않습니다 | 권장 |
| 진단서는 계정 공유를 받은 날부터 3영업일 안에 드립니다. 첫 화면에 이 기한을 약속합니다 (`Landing-adflow.md` 3.8) | 확정 (2026-11-11) |
| 진단서는 계약하지 않아도 고객이 가져갑니다 | 권장 |

- **진단서를 미끼로 두는 이유 (확정).** 다른 대행사 상담은 말로 설명합니다. 우리는 고객 자신의 광고로 "이렇게 배운다"를 먼저 보여 줍니다.
- 진단서 대부분은 AdFlow의 "Meta 지난 광고 가져오기"와 "첫 실험 후보 제안"으로 만듭니다. 그래서 진단은 제품 기능을 매번 시험하는 기회이기도 합니다.

## 6. 제안과 가격

| 규칙 | 상태 |
|---|---|
| 가격은 사업 구조 문서 3절의 표 그대로입니다. 고객마다 가격을 깎지 않습니다 | 권장 |
| 할인은 첫 달 50% 하나뿐입니다 | 확정 (사업 구조 문서 4절) |
| 월 광고비 300만 원 이하는 라이트, 그보다 크면 스탠다드를 제안합니다 | 확정 |
| 제안서에는 진단서, 첫 달 실험 계획 초안, 가격, 계약 조건(3개월, 평일 대응, 고객 제공 재료)을 넣습니다 | 권장 |

- **가격을 깎지 않는 이유 (권장).** 고객마다 가격이 다르면 직원 한 명당 매출을 예측할 수 없습니다. 고객끼리 가격을 알게 되면 신뢰도 잃습니다.

## 7. 영업 목표

재무 문서의 기본 시나리오는 처음 6개월 동안 매달 대행 고객 2곳이 새로 들어옵니다.
이를 위해 매달 필요한 문의 수를 거꾸로 계산합니다. 전환율은 모두 가설입니다.

| 단계 | 전환율 (가설) | 매달 필요한 수 |
|---|---|---|
| 계약 | — | 2곳 |
| 진단 → 계약 | 30% | 진단 7건 |
| 문의 → 진단 (기준 충족) | 50% | 문의 14건 |

- 진단 7건은 직원 시간으로 월 7시간입니다. 감당할 수 있는 양입니다.
- 첫 3개월 동안 실제 전환율을 재고 이 표를 고칩니다.

## 8. 매달 볼 숫자

| 숫자 | 정의 | 경고 기준 |
|---|---|---|
| 문의 수 | 그달 들어온 대행 문의 | 2개월 연속 10건 미만 |
| 진단 → 계약 전환율 | 그달 계약 수 ÷ 그달 진단 수 | 3개월 평균 20% 미만 |
| 문의 경로 | 실험 공개, Meta 광고, 소개, 기타 | 한 경로가 80%를 넘으면 다른 경로를 늘립니다 |
| 기준 미달 문의 중 구독 가입 | 구독을 안내한 문의 중 가입한 비율 | 기록만 합니다 |
| 진단 1건 직원 시간 | 진단에 쓴 시간 평균 | 1시간 초과 |

- 진단 → 계약 전환율이 낮으면 진단서 내용부터 고칩니다. 문의 수가 적으면 실험 공개 횟수와 Meta 광고를 먼저 봅니다 (권장).

## 9. 제품에 반영할 것

2026-11-11에 정책서 27절에 넣었습니다. 1차에 넣은 것은 사례 공개 동의 표시와 문의 경로 기록입니다. 문의 자동 등록, 진단서 자동 생성, 공개 글 초안 자동 생성은 1차에서는 직원이 직접 하고, 손이 많이 가면 더합니다 (기획서 6.2).

| 기능 | 이유 | 관련 절 |
|---|---|---|
| 문의 양식에서 들어온 문의를 고객사 "문의" 상태로 자동 등록 | 영업 기록이 처음부터 AdFlow에 남습니다 | 2 |
| 무료 진단서 만들기 (지난 광고 가져오기와 첫 실험 후보 제안을 한 장으로 묶음) | 진단 1시간 목표를 지킵니다 | 5 |
| 실험 기록에서 공개 글 초안 만들기 (고객 이름, 금액 자동 제거) | 매주 공개를 지킵니다 | 3.1 |
| 고객사에 "사례 공개 동의" 표시 | 동의하지 않은 고객의 실험을 공개하지 않게 막습니다 | 3.1 |
| 고객사에 "문의 경로" 기록 | 경로별 숫자를 봅니다 | 8 |

## 10. 정해야 할 것

| 항목 | 정하는 방법 |
|---|---|
| 진단을 위해 계약 전에 광고 계정을 읽기 권한으로 공유받을 수 있는지 | Meta 비즈니스 관리자 문서 확인 |
| 익명 사례 공개 동의 조항 문구 | 법·행정 단계에서 계약서와 함께 정함 |
| 진단 → 계약, 문의 → 진단 전환율 | 첫 3개월 실제 숫자로 고침 |
| 실험 공개 글을 어디에 가장 먼저 올릴지 | 첫 2개월 채널별 문의 경로 숫자로 정함 |
