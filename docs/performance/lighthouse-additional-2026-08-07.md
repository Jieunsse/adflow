## 1. 소재 라이브러리 이미지 전송량

`/library`의 1024px 데모 PNG 두 장이 CSS 배경 이미지로 즉시 내려와 전체 전송량의 약 80%를 차지했어요. 같은 해상도의 WebP로 교체하고, 토너먼트·브랜드 프로필·Instagram 데모 등 모든 참조도 함께 바꿨어요.

| 항목 | 개선 전 | 개선 후 | 변화 |
| --- | ---: | ---: | ---: |
| Lighthouse Performance | 75 | 80 | +5점 |
| LCP | 18.2초 | 5.4초 | 12.7초 단축 (70%) |
| 전체 전송량 | 3,070KiB | 658KiB | 2,412KiB 절감 (79%) |
| 두 이미지 전송량 | 2,504KB | 33KB | 2,471KB 절감 (99%) |

## 포트폴리오 기재용 성능 개선

- 대시보드 첫 화면이 폰트 weight 4~5종을 함께 요청해 4.22MB를 전송하고 핵심 문구 렌더를 23초간 막던 문제를 확인, 디자인 토큰의 시스템 폰트 대체 체인을 기본값으로 돌려 LCP 23.9초 → 3.3초, 전송량 306KB로 축소
- 로그인 화면의 렌더 블로킹 원인이 CSS의 외부 폰트 import이고 이미 로컬 폰트 선언과 중복임을 확인, 중복만 걷어내 FCP 21.6초 → 4.8초, LCP 22.8초 → 6.3초
- 소재 라이브러리에서 1024px PNG 두 장이 첫 화면 전송량 2.5MB를 차지하는 것을 확인, 같은 해상도 WebP로 전환해 이미지 전송량 2.50MB → 33KB, 전체 전송량 3.07MB → 658KB, LCP 18.2초 → 5.4초
- 광고 만들기 첫 단계에 생성·비교·이미지·게재 UI가 함께 실리던 구조를 단계 진입 시 동적 로딩으로 전환해 초기 JS 301KB → 253KB, 미사용 JS 64KB → 27KB, TBT 33ms → 20ms
- 캠페인 상세 기본 탭에서 편집 전용 날짜·연령 UI와 A/B 결과 카드를 지연 로딩해 초기 JS 253KB → 237KB, LCP 3.2초 → 2.9초, Lighthouse 93 → 95

원본 Lighthouse JSON은 로컬 `.scratch/lighthouse-extra-before/` 및 `.scratch/lighthouse-extra-after/`에 보관했어요. `npm run build`를 통과했고, 생성 플로우와 캠페인 일정 편집 UI의 지연 청크 로딩도 브라우저에서 확인했어요.
