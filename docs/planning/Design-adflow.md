# AdFlow 디자인 설계 초안

작성일: 2026-11-11 · 상태: 초안 (확정 전)
근거 문서: 기획서(`PRD-adflow.md`), 정책서(`Policy-adflow.md`), 회사 설계(`docs/company/01`~`07`), 디자인 토큰(`apps/web/app/styles/design-system.css`), 에이전트 규칙(`AGENTS.md`의 Design System 절)

상태 표기는 정책서 0.2절과 같습니다. 확정은 정한 것, 권장은 제안하는 안, 미결정은 사용자가 정해야 하는 것입니다.

## 0. 이 문서의 범위

이 문서는 기능명세가 없어도 정할 수 있는 디자인 결정만 다룹니다.
화면 하나하나의 입력 칸, 버튼 순서, 예외 흐름은 기능명세가 끝난 뒤에 정합니다 (9절).

| 이 문서에서 정하는 것 | 기능명세 뒤로 미루는 것 |
|---|---|
| 디자인 원칙 | 화면별 와이어프레임 |
| 누가 어떤 기기로 어떤 화면 묶음을 보는지 | 화면별 입력 칸과 검사 규칙 |
| 메뉴 구조의 큰 틀 | 화면 사이 이동의 세부 흐름 |
| 색, 글자, 간격, 모서리, 그림자의 역할 | 컴포넌트의 세부 변형(크기, 상태 전부) |
| 실험 상태와 기록 상태를 화면에 표시하는 방법 | 각 화면의 빈 상태와 오류 문구 전체 |
| 여러 화면에 반복되는 공통 패턴 | |

## 1. 디자인 원칙

기획서의 약속을 화면 규칙으로 옮긴 것입니다. 디자인 판단이 갈리면 위의 원칙이 이깁니다.

1. **결정이 먼저, 숫자는 근거로.** 화면 맨 위에는 "지금 할 일"을 둡니다. 숫자와 차트는 그 결정을 뒷받침하는 자리에만 둡니다. 숫자만 늘어놓은 화면은 만들지 않습니다 (기획서 7절의 하지 않는 것).
2. **근거가 없는 말은 보여 주지 않습니다.** 제안, 리포트의 이유, AI 문장에는 어느 실험이나 어느 기간의 숫자에서 왔는지 항상 붙입니다 (정책서 15절).
3. **출처를 섞지 않습니다.** 확정된 브랜드 지식, 과거 기록(참고), AI 초안은 모양으로 구분합니다. 읽는 사람이 무엇을 믿어도 되는지 바로 알 수 있어야 합니다 (정책서 14.2, 14.3).
4. **판정 전에는 결론처럼 보이지 않게 합니다.** 데이터를 모으는 중인 실험은 이기고 있는 쪽을 보여 주지 않습니다. 진행 표시는 "판정까지 얼마나 남았는지"로만 보여 줍니다 (정책서 5.1, 12절).
5. **돈이 나가는 버튼은 한 번 더 확인합니다.** 게재 승인, 예산 늘리기, 월간 계획 승인은 금액과 기간을 보여 주는 확인 단계를 거칩니다.
6. **보는 사람에 맞춰 덜어냅니다.** 직원 화면은 한 화면에서 많이 처리하게 만듭니다. 고객 화면은 결과만 남기고 나머지는 덜어냅니다.

## 2. 누가 어떤 기기로 보는가

| 사람 | 주로 하는 일 | 기기 | 화면 성격 | 출시 | 상태 |
|---|---|---|---|---|---|
| 우리 대행팀 직원 | 여러 브랜드의 실험을 만들고 승인하고 기록을 확정 | 데스크톱 (1440 기준, 최소 1280) | 작업 화면. 정보가 많고 한 화면에서 처리 | 1차 | 권장 |
| 대행 고객 (대개 대표) | 월간 계획 승인, 리포트 읽기, 배운 것 읽기 | 데스크톱 먼저, 휴대폰은 반응형으로 지원 | 읽는 화면. 결과 중심, 버튼은 승인 하나 | 1차 | 확정 |
| 개인 구독 (1인 창업자) | 직원과 같은 일을 혼자, 짧게 | 데스크톱 먼저, 휴대폰에서 확인과 승인 | 작업 화면을 줄인 형태 | 2차 | 권장 |
| 팀 구독 마케터 | 직원과 같음 | 데스크톱 | 작업 화면 | 3차 | 권장 |

- **고객 화면은 데스크톱 먼저, 휴대폰은 반응형 (확정, 2026-11-11).** 시안은 데스크톱 너비로 먼저 그립니다. 휴대폰 화면은 따로 설계하지 않고, 같은 화면이 좁은 너비에서도 깨지지 않게 줄어드는 것까지만 지원합니다. 1차의 월간 리포트 링크는 카카오톡 채널로 보내므로 휴대폰에서 열릴 수 있습니다 (기획서 6.2의 6번). 그래서 375 너비에서 글자가 잘리거나 가로로 밀리지 않는지는 확인합니다.
- **직원 화면은 데스크톱만 (권장).** 지금 대부분의 화면이 1440 고정입니다 (`src/widgets/sidebar/WorkspaceNav.tsx` 주석). 1차에는 휴대폰 대응을 하지 않습니다. 단, 게재 승인과 자동 멈춤 알림 확인은 휴대폰에서도 할 수 있게 합니다. 밤이나 주말에 자동 멈춤이 걸리면 담당 직원이 밖에서 확인해야 하기 때문입니다 (운영 문서 6절).

## 3. 화면 묶음과 메뉴의 큰 틀

### 3.1 직원 작업 화면 (1차)

메뉴는 "일하는 순서"대로 둡니다. 기획서 6.1의 핵심 흐름과 같은 순서입니다.

| 메뉴 | 담는 것 | 근거 | 상태 |
|---|---|---|---|
| 오늘 할 일 | 담당 브랜드 전체 또는 브랜드 하나의 할 일 3개, 그 아래 성과 요약 | 정책서 15절, 기획서 6.2의 5·10번 | 권장 |
| 광고 실험 | 목표, 실험 묶음, 실험 목록과 상태 | 정책서 8·9절 | 권장 |
| 광고 승인 대기 | 게재 승인 대기, 월간 계획 | 정책서 11절 | 권장 |
| 광고 노하우 | 확정 기록, 초안, 과거 기록(참고) | 정책서 14절 | 권장 |
| 성과 리포트 | 주간, 월간 | 정책서 16절 | 권장 |
| 브랜드 정보 | 프로필, 브랜드 규칙, 참고 자료 | 정책서 6·7절 | 권장 |
| 고객사 관리 | 영업 단계, 담당 직원, 작업 시간(탭) | 정책서 27·28절 | 권장 |
| 설정 | 연결, 사람과 역할, AI | 정책서 4·5·18절 | 권장 |

- **브랜드 바꾸기는 메뉴 맨 위에 고정 (권장).** 직원은 여러 브랜드를 오가며 일합니다. 지금 어느 브랜드를 보고 있는지 항상 보여야 합니다. "모든 담당 브랜드"를 고르면 오늘 할 일과 광고 승인 대기만 모아 보여 주고, 나머지 메뉴는 브랜드를 고르라고 안내합니다.
- **잘못된 브랜드에서 일하는 실수를 막습니다 (권장).** 게재 승인처럼 돈이 나가는 확인 창에는 브랜드 이름과 브랜드 색 표시를 크게 넣습니다.
- **숨기는 기능 (확정).** 정책서 22절의 화면은 메뉴에 넣지 않습니다.

### 3.2 고객 화면 (1차)

| 화면 | 담는 것 | 상태 |
|---|---|---|
| 이번 달 | 월간 계획 승인 요청(있을 때만 맨 위), 이번 달 쓴 돈과 남은 상한, 진행 중인 실험 수 | 권장 |
| 리포트 | 월간 리포트. "성과, 이유, 다음 할 일" 순서 | 확정 (정책서 16.3) |
| 배운 것 | 확정된 기록만. 초안과 과거 기록은 보여 주지 않음 | 권장 |
| 진행 중인 실험 | 읽기만. 이기고 있는 쪽은 보여 주지 않음 | 확정 (정책서 5.1) |

- 데스크톱에서는 위쪽 탭 4개로 둡니다. 좁은 너비에서는 같은 탭이 가로로 넘겨 보는 형태로 줄어듭니다 (권장).
- 고객 화면에서는 소재 만들기, 브랜드 규칙, 설정, 영업 기록, 작업 시간, 다른 브랜드가 보이지 않습니다 (정책서 5.1, 확정).

### 3.3 구독 화면 (2차, 3차)

직원 작업 화면에서 "고객사" 메뉴와 브랜드 바꾸기를 뺀 형태로 시작합니다 (권장). 직접 올리기 모드의 결과 파일 올리기 화면은 2차 기능명세에서 정합니다.

- **로고는 이름이 확정된 뒤에 확정합니다 (권장).** 글자 로고는 이름 그 자체라서, 상표 검색에 걸려 이름을 바꾸면 로고를 다시 만들어야 합니다. 1번(브랜드 핵심)과 3·4번(색, 글꼴)은 이름과 관계없으니 상표 검색을 기다리지 않고 먼저 해도 됩니다.
- **작업 위치 (확정, 2026-11-11).** 리브랜딩은 피그마 AdFlow 파일의 Branding 페이지에서 바로 진행합니다. 정책과 기능명세처럼 마지막에 한꺼번에 넣지 않습니다. 첫 판에는 기준판과 방향 시안 3개(A 실험실, B 기록, C 신호)를 올렸습니다.
- **제품 밖에도 씁니다.** 새 브랜드는 실험 공개 글, Meta 광고(월 50만 원, 영업 문서), 무료 광고 계정 진단서, 계약서와 청구서, 카카오톡 채널 프로필에도 씁니다. 그래서 로고와 색은 화면뿐 아니라 문서와 광고 이미지에서도 잘 보이는지 확인합니다.

- **디자인 시스템 먼저 (확정, 2026-11-11).** 이름과 로고는 뒤로 미루고 색, 글꼴, 여백, 모서리, 그림자부터 정합니다. 바탕은 방향 A "실험실"이고, 인디고의 채도를 낮춰 정돈된 톤으로 씁니다. 값은 `DesignSystem-adflow.md`, 피그마는 Design System 페이지에 있습니다.

### 4.3 브랜드 핵심 초안

기획서에서 가져온 재료입니다. 1번 단계에서 고르고 고칩니다.

| 항목 | 초안 | 근거 | 상태 |
|---|---|---|---|
| 한 줄 콘셉트 | 브랜드의 광고 실험실 | 기획서 1절 | 확정 |
| 비전 | 모든 광고가 다음 광고를 더 낫게 만든다 | 기획서 1절 | 확정 |
| 성격 키워드 1 | 근거가 있는. 차분하고 정확하게 말합니다 | 디자인 원칙 1, 2 | 권장 |
| 성격 키워드 2 | 실험하는. 해 보고 확인합니다 | 콘셉트 | 권장 |
| 성격 키워드 3 | 쌓이는. 쓸수록 회사에 남습니다 | 대표에게 한 약속 (기획서 5절) | 권장 |
| 말투 | 해요체. 과장하지 않고 숫자로 말합니다 | `AGENTS.md` UX 라이팅 | 확정 |
| 피할 것 | 광고 업계의 화려하고 과장된 느낌, "AI가 알아서 다 해 준다"는 마법 같은 느낌 | 디자인 원칙 2. 근거 없는 말을 하지 않는다는 약속과 맞지 않습니다 | 권장 |

| 한글 글꼴은 숫자가 고정 폭으로 맞춰지는 글꼴로 고릅니다 | 표와 지표 숫자를 비교하기 쉽습니다 (4.5) | 권장 |
| 심볼은 16×16 파비콘 크기에서도 알아볼 수 있습니다 | 브라우저 탭과 카카오톡 채널 프로필에 작게 보입니다 | 권장 |
| 로고는 흰 바탕, 어두운 바탕, 한 가지 색 세 가지 버전이 있습니다 | 계약서와 청구서는 흑백으로 인쇄될 수 있습니다 | 권장 |
| 상업용으로 무료로 쓸 수 있는 글꼴만 씁니다 | 웹, 광고 이미지, 문서에 모두 쓰기 때문입니다 | 권장 |

### 4.5 브랜드와 관계없이 지금 정하는 것

| 항목 | 안 | 상태 |
|---|---|---|
| 숫자 정렬 | 표와 지표 숫자는 고정 폭 숫자(`tabular-nums`)로 맞춥니다 | 권장 |
| 금액 표기 | `1,250,000원`처럼 원 단위 전체. 공간이 좁은 곳만 `125만 원` | 권장 |
| 비율 표기 | 소수점 한 자리 `2.4%`. 차이는 `+0.6%p`처럼 퍼센트포인트로 | 권장 |
| 강조 판 | 한 화면에 눈에 띄는 강조 판은 하나만 둡니다. 오늘의 결정 맨 위가 그 자리입니다 | 권장 |
| 다크 모드 | 1차에는 만들지 않습니다 | 권장 |

## 5. 상태를 화면에 표시하는 법

### 5.1 의미를 가진 색 다섯 가지

상태가 많아도 색은 다섯 가지만 씁니다. 색이 많으면 아무 색도 눈에 띄지 않기 때문입니다.

| 색 역할 | 뜻 | 지금 토큰 (리브랜딩 때 새 색으로 바꿈) | 상태 |
|---|---|---|---|
| 막힘 | 돈이 새거나 광고가 멈춤. 지금 손대야 함 | `--w-status-negative` 계열 | 권장 |
| 기다림 | 사람이 처리해야 다음으로 넘어감 | `--w-status-cautionary` 계열 | 권장 |
| 진행 | 정상으로 돌아가는 중 | `--w-status-info` 계열 | 권장 |
| 끝남 | 결과가 나옴 | `--w-status-positive` 계열 | 권장 |
| 조용함 | 작성 중, 취소, 보관 | 회색 (`--w-fg-alternative`, `--w-fill-normal`) | 권장 |

- **이김과 짐에 빨강, 초록을 쓰지 않습니다 (권장).** 실험에서 "진 소재"는 실패가 아니라 배운 것입니다. 빨강을 쓰면 막힘과 헷갈립니다. 이긴 쪽은 굵은 글씨와 "이김" 글자로 표시합니다.
- **색만으로 구분하지 않습니다 (권장).** 모든 상태 표시에는 글자를 함께 씁니다. 색을 구분하기 어려운 사람도 읽을 수 있어야 합니다.

### 5.2 실험 상태와 색 (정책서 9.5)

| 화면 표시 | 색 역할 |
|---|---|
| 작성 중, 소재 준비 중 | 조용함 |
| 승인 대기, 반려됨 | 기다림 |
| Meta 검토 중, 데이터 모으는 중 | 진행 |
| Meta 거절, 멈춤 | 막힘 |
| 결과 나옴 | 끝남 |
| 판정 불가 | 기다림 (기록 확정을 사람이 해야 하므로) |
| 취소됨 | 조용함 |

- 고객 화면에서는 위 상태를 "준비 중, 진행 중, 결과 나옴, 멈춤" 네 가지로 줄여 보여 줍니다 (권장). 대표에게 Meta 검토와 사내 승인의 차이는 필요 없기 때문입니다.

### 5.3 기록의 출처 표시 (정책서 14절)

| 출처 | 모양 | 상태 |
|---|---|---|
| 확정된 브랜드 지식 | 실선 테두리 카드, "확정" 글자, 확정한 사람과 날짜 | 권장 |
| 초안 | 점선 테두리 카드, "초안" 글자, 확정 버튼 | 권장 |
| 과거 기록 (참고) | 회색 바탕 카드, "과거 기록 (참고)" 글자. 지식과 같은 목록에 섞지 않고 따로 둠 | 권장 |
| AI가 쓴 문장 | 문장 옆에 "AI 정리" 표시와 근거 링크. 어떤 AI로 만들었는지는 펼치면 보임 | 권장 |
| 보관 | 접힌 목록, 보관 이유 표시 | 권장 |
