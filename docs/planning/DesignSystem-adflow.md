피그마: AdFlow 파일의 Design System 페이지 (변수, 글자 스타일, 그림자 스타일)

## 1. 색

### 1.1 만드는 방법

- 모든 색은 같은 밝기 단계(50~900)로 만듭니다. 같은 번호끼리는 밝기가 비슷해서, 색만 바꿔도 대비가 크게 달라지지 않습니다.
- 인디고는 A 시안(`#3F37C9`)보다 채도를 낮췄지만, 회색처럼 보이지 않을 만큼은 남겼습니다 (2026-11-12에 처음 안보다 약 1.7배 올림). 상태 색은 처음 안보다 20% 낮춰 화면 전체의 톤을 맞춥니다.
- 회색에는 인디고 쪽 푸른 기운을 아주 조금 넣었습니다. 주 색과 회색이 따로 놀지 않게 하기 위해서입니다.

| 이름 | 크기 / 줄 높이 | 굵기 | 쓰는 곳 |

- 작업 화면의 기본 본문은 14px(`body/2`)입니다. 직원이 한 화면에서 많이 처리해야 하기 때문입니다. 고객이 읽는 리포트는 16px(`body/1`)을 씁니다.
- 반픽셀이나 단계 밖의 크기는 쓰지 않습니다 (`AGENTS.md` 규칙 유지).
- 큰 글자는 글자 사이를 조금 좁힙니다. `display/strong`과 `number/lg`는 -0.5%, `heading/1`은 -0.3%, `heading/2`는 -0.2%입니다. 나머지는 0입니다.

## 5. 그림자

그림자는 "화면 위에 떠 있는 층"에만 씁니다. 일반 카드는 그림자 없이 `line/default` 테두리로 나눕니다 (`AGENTS.md` 규칙 유지).
그림자 색은 검정이 아니라 회색 900(`#191A20`)에 투명도를 준 것입니다. 푸른 기운이 섞여 화면 톤과 맞습니다.

| 이름 | 값 | 쓰는 곳 |
|---|---|---|
| `shadow/raised` | 0 1 2 6%, 0 2 6 4% | 화면에 붙어 있는 핵심 요약, 스크롤해도 따라오는 패널 |
| `shadow/overlay` | 0 4 12 8%, 0 12 32 8% | 드롭다운, 팝오버, 토스트 |
| `shadow/modal` | 0 8 24 12%, 0 24 64 16% | 창, 옆에서 나오는 시트 |

(값은 "가로 세로 흐림 투명도" 순서입니다.)

## 6. 지금 코드와의 관계

- 지금 화면은 Wanted 토큰(`--w-*`)과 Pretendard를 씁니다.
- 새 디자인 시스템은 shadcn/ui 위에 짓습니다 (2026-11-11 세팅). 색 값은 `apps/web/app/styles/shadcn.css`, Tailwind 색 이름은 `tailwind.config.ts`, 부품은 `src/shared/ui/kit/`에 있습니다. 사용 규칙은 `AGENTS.md`의 "새 UI 부품" 절에 있습니다.
- shadcn 색 이름과 이 문서 역할 색의 짝: `background`=bg/surface, `foreground`=fg/default, `primary`=primary/default(+hover, pressed), `secondary`=primary/soft, `muted`=bg/subtle, `muted-foreground`=fg/muted, `accent`=마우스 올림 바탕, `destructive`=막힘 진한 색, `border`=line/default, `input`=line/strong, `ring`=focus/ring, `chart-1~5`=차트 계열, `status-*`=상태 색.
- 글꼴(IBM Plex)과 글자 단계, 여백 변수는 아직 코드에 넣지 않았습니다. 화면을 새 디자인으로 옮기는 작업 때 함께 넣습니다.

## 8. 기본 부품 (1차)

피그마 Components 페이지에 있습니다. 왼쪽은 원본 부품이고, 오른쪽 "Components · 사용 예시" 판은 원본을 가져다 쓴 예시입니다.
모든 색, 여백, 모서리, 글자는 1~5절의 변수와 스타일에 연결돼 있습니다.

| 부품 | 변형 | 바꿀 수 있는 글자 | 규칙 |
|---|---|---|---|
| Button | 종류 4 (Primary, Soft, Outline, Ghost) × 크기 2 (보통 44, 작게 32) × 상태 3 (기본, 마우스 올림, 쓸 수 없음) = 24개 | 라벨 | Primary는 한 화면에 하나만 둡니다. 돈이 나가는 확인 버튼은 Primary에 금액을 넣습니다 (예: "50만 원 승인하기"). 라벨은 동사 하나로 씁니다 |
| Status Badge | 상태 5 (막힘, 기다림, 진행, 끝남, 조용함) | 라벨 | 라벨에는 화면 표시 이름(예: 승인 대기)을 넣습니다. 색은 `Design-adflow.md` 5.2의 대응표를 따릅니다 |
| Text Field | 상태 4 (기본, 포커스, 오류, 쓸 수 없음) | 이름, 값, 안내 | 이름은 위, 안내와 오류는 아래에 둡니다. 포커스는 주 색 2px 테두리, 오류는 막힘 색 2px 테두리입니다 |
| Nav Item | 상태 3 (기본, 마우스 올림, 선택됨) | 라벨 | 지금 보고 있는 메뉴만 선택됨으로 둡니다 |

- **버튼 높이.** 보통 크기는 44px입니다. 휴대폰에서 누르는 곳은 44×44 이상이라는 접근성 규칙(`Design-adflow.md` 7절)에 맞췄습니다.
- **눌림 상태는 아직 그리지 않았습니다.** 변수(`primary/pressed`)는 있으니 코드에서는 바로 쓸 수 있습니다. 변형이 30개를 넘지 않게 하려고 피그마에서는 뺐습니다.
- **입력 칸의 안내 문구.** 피그마 원본에서는 네 상태가 같은 안내 문구를 보여 줍니다. 오류 문구 같은 상태별 문구는 가져다 쓸 때 "안내" 글자를 바꿔 넣습니다.
- 버튼의 보조 버튼 마우스 올림 색을 위해 역할 색 `primary/soft-hover`(인디고 100)를 하나 더했습니다.

| Toggle | 켜짐 2 × 상태 2 | 누르는 즉시 적용되는 설정 (예: 밤과 주말 자동 멈춤). 저장 버튼을 따로 누르는 설정에는 Checkbox를 씁니다 |
| Select | 상태 3 (기본, 포커스, 쓸 수 없음) | 보기 중 하나를 고르는 칸. 누르면 Menu가 열립니다 |
| Menu, Menu Item | Menu Item 상태 3 (기본, 마우스 올림, 선택됨) | 드롭다운 목록. 그림자는 `shadow/overlay` |
| Tab | 상태 3 (기본, 마우스 올림, 선택됨) | 같은 화면 안에서 보기를 바꿀 때. 고른 탭에만 주 색 2px 밑줄. 다른 화면으로 갈 때는 Nav Item |
| Card | 2 (Flat, Raised) | 기본은 Flat(테두리). Raised는 따라오는 요약 패널에만 |
| Decision Card | 1 | 오늘의 결정 카드. 상태 배지, 할 일 한 문장, 근거 한 줄, 주 버튼과 "나중에" (`Design-adflow.md` 6절의 결정 카드) |
| Judgement Progress | 2 (모으는 중, 판정 가능) | 판정까지 남은 노출 수. 이기고 있는 쪽은 보여 주지 않습니다 (정책서 5.1) |
| Toast | 2 (기본, 오류) | 잠깐 뜨는 결과 알림. 행동은 하나까지 (되돌리기, 다시 시도) |
| Dialog | 2 (Basic, Money) | Basic은 되돌리기 어려운 일 확인. Money는 돈이 나가는 일 확인이며 브랜드 이름, 금액, 기간을 크게 보여 주고 버튼에 금액을 넣습니다 (`Design-adflow.md` 6절의 돈 확인 창) |
| Table Cell | 4 (머리, 글자, 숫자, 상태) | 숫자 칸은 오른쪽 정렬에 IBM Plex Mono. 상태 칸에는 Status Badge. 머리 줄은 `bg/subtle` 바탕 |

- **변형마다 다른 문구.** 피그마는 같은 이름의 글자 속성을 변형끼리 하나로 묶습니다. 그래서 Toast의 오류 문구, Dialog의 Money 제목처럼 변형마다 다른 문구는 원본에서 기본 문구로 보입니다. 가져다 쓸 때 글자를 바꿔 넣습니다 (예시판은 바꿔 넣었습니다).
- **체크 표시와 화살표.** 체크박스의 체크 표시는 `check`, Select의 화살표는 `chev-down` 아이콘 부품을 씁니다. 체크박스의 "일부만" 표시(가로줄)는 맞는 아이콘이 없어 그대로 둡니다.

## 10. 차트 색

피그마 Design System 페이지의 "차트 색" 절에 있습니다. 변수는 Color 컬렉션의 `chart/*`입니다.

### 10.1 계열 색

| 순서 | 변수 | 값 | 색 |
|---|---|---|---|
| 1 | `chart/series-1` | `#4D56BF` | 인디고 (주 색과 같음) |
| 2 | `chart/series-2` | `#E1773B` | 주황 |
| 3 | `chart/series-3` | `#973069` | 자두색 |
| 4 | `chart/series-4` | `#7F8015` | 올리브 |
| 5 | `chart/series-5` | `#7B428C` | 보라 |
| 기준 | `chart/baseline` | 회색 500 | 실험의 기준 소재 |

- **고른 방법.** 색상, 밝기, 순서의 조합 약 1만 3천 가지를 차트 색 검사기로 돌려, 모든 검사를 통과한 것 중 이웃끼리 가장 잘 구분되는 조합을 골랐습니다.
- **검사 결과.** 이웃한 두 색의 차이는 적록 색약 시뮬레이션에서 16.0(기준 8 이상), 일반 시력에서 24.7(기준 15 이상)입니다. 다섯 색 모두 흰 바탕과의 대비가 3:1 이상입니다. 앞의 3개는 아무 두 색이 붙어도 구분됩니다.
- **상태 색과 나눔.** 상태 색(빨강, 호박색, 하늘색, 초록)과 다른 색 계열을 썼습니다. 차트의 한 계열이 "막힘"이나 "끝남"처럼 읽히지 않게 하기 위해서입니다.
- **차트 1번 색은 주 색과 같습니다.** 차트 색은 채도 0.10 이상이어야 회색처럼 보이지 않습니다. 옛 주 색(`#555F9B`)은 이 기준에 못 미쳐서 차트에는 따로 진한 `#5259AC`를 썼습니다. 2026-11-12에 주 색을 `#4D56BF`(채도 0.16)로 바꾸면서 기준을 넘었으므로, 1번 계열도 주 색을 그대로 씁니다.

### 10.2 그 밖의 차트 색

| 쓰는 곳 | 색 |
|---|---|
| 크기 (한 색, 연한 것에서 진한 것으로) | 인디고 100~800. 순서가 있는 막대(단계, 구간)는 배경과 구분되도록 400부터 씁니다 |
| 늘고 줆 | 주황 3단계(줄어듦), 회색 200(가운데), 인디고 300·500·700(늘어남). 늘어난 것이 꼭 좋은 일은 아니라서(예: 전환 비용) 빨강과 초록을 쓰지 않습니다 |
| 격자 줄 | `chart/grid` (회색 100) |
| 기준 축 | `chart/axis` (회색 300) |

### 10.3 차트 규칙

| 규칙 | 이유 |
|---|---|
| 계열 색은 항상 1번부터 순서대로 씁니다. 필터로 계열이 줄어도 남은 계열의 색은 바꾸지 않습니다 | 색 순서가 색약 구분을 지켜 줍니다. 색이 바뀌면 같은 대상을 다른 것으로 읽습니다 |
| 5개를 넘으면 작은 것을 "그 밖"으로 묶습니다 | 6번째 색은 검사를 통과하지 못합니다 |
| 실험 비교는 기준 소재를 `chart/baseline`(회색), 바꾼 소재를 1번 계열로 그립니다. 이김과 짐을 색으로 나누지 않습니다 | `Design-adflow.md` 5.1 |
| 판정 전 실험의 성과 숫자는 차트로 그리지 않습니다. 판정까지 남은 정도만 보여 줍니다 | 정책서 5.1, 12절 |
| 축은 하나만 씁니다. 단위가 다른 두 숫자는 차트를 둘로 나눕니다 | 두 축 차트는 읽는 사람이 관계를 잘못 읽게 만듭니다 |
| 계열이 2개 이상이면 범례를 둡니다. 4개 이하면 선 끝에도 이름을 붙입니다 | 색만으로 계열을 구분하지 않게 하기 위해서입니다 |
| 숫자는 강조할 점에만 붙입니다. 글자는 계열 색이 아니라 글자 색(`fg/*`)으로 씁니다 | 숫자가 많으면 읽을 것이 흐려집니다 |
| 선은 2px, 점은 8px 이상, 막대 끝은 모서리 4. 마우스를 올리면 그 지점의 숫자를 보여 줍니다 | |
| 차트 아래에 같은 숫자를 담은 표 보기를 둡니다 | 화면 읽기 프로그램을 쓰는 사람과 정확한 숫자가 필요한 사람을 위해서입니다 |

### 11.2 부품의 아이콘 자리

|---|---|---|---|
| Button | `Show icon`(켜기·끄기), `Icon`(아이콘 바꾸기) | 꺼짐, `plus` | 보통 20px, 작게 16px. 색은 버튼 글자 색과 같습니다. 아이콘은 글자 앞에 둡니다 |

- **아이콘을 바꿨을 때의 색.** 다른 아이콘으로 바꾸면 선의 이름이 달라 색이 기본 글자 색으로 돌아갈 수 있습니다. 주 버튼처럼 바탕이 진한 곳에서는 바꾼 뒤 색을 확인합니다. 코드에서는 아이콘이 글자 색(`currentColor`)을 따르므로 이 문제가 없습니다.

### 12.4.1 진행 (2026-11-11): 12.2~12.4 24종도 모두 만들었습니다

피그마 Components 페이지 왼쪽 아래에 원본이 있고, 오른쪽 열의 "Components · 사용 예시 4차" 판에 기능명세 화면 조각(실험 만들기, 소재와 승인, 배운 것, 리포트, 고객사, 날짜·파일·로그인·진행)으로 조합해 두었습니다. 예시판 1~4차는 모두 오른쪽 열(x=2000)로 모았습니다.

| 묶음 | 피그마 이름 |
|---|---|
| 입력 | Textarea, Money Field, Password Field, Choice Chip, Segment·Segmented Control, Choice Card, Date Field·Calendar, Filter Chip·Filter Bar, Upload Dropzone·File Row, Social Login Button |
| 흐름 | Kanban Card·Kanban Column, Timeline Item, Checklist Item·Setup Checklist, Meter, Sort Header·Table Row |

- **Step·Stepper는 뺐습니다 (2026-11-11).** 번호 원과 선으로 단계를 잇는 모양이 흔한 AI 생성 화면처럼 보인다는 의견이 있었습니다. 쓰던 곳은 실험 만들기(1-1) 하나였고, 한 화면 양식과 오른쪽 실험 요약 패널로 바꿨습니다 (`Features-adflow.md` 화면 1-1). 다른 화면에도 단계 표시를 새로 만들지 않습니다.
- **소셜 로그인 버튼의 로고 자리**는 임시 글자(K, G, f)입니다. 각 회사가 배포한 공식 로고 파일로 바꿔야 합니다. 색과 모서리는 각 회사 규정 값을 직접 넣었습니다 (우리 변수 아님).
- **광고 미리보기**는 Meta 화면을 닮게 그린 것입니다. 실제 게재 모습과 조금 다를 수 있다고 화면에 적습니다.
- **변형마다 다른 문구.** 9절의 주의와 같습니다. Learning Card, Metric Tile, Meter, Choice Card, Textarea처럼 상태마다 문구가 다른 부품은 원본에서 기본 문구로 보입니다. 가져다 쓸 때 바꿔 넣습니다.
- 코드에서 짝이 되는 shadcn 부품: Textarea=Textarea, Choice Chip·Segmented Control=Toggle Group, Choice Card=Radio Group, Calendar·Date Field=Calendar·Popover, Filter Bar=Dropdown Menu, Kanban·Timeline·Learning Card·Ad Preview 등은 shadcn에 없어서 `src/shared/ui/kit/` 위에 우리 부품으로 만듭니다. ### 12.5 정리

- (2026-11-11 갱신) 12.1~12.4의 부품을 모두 만들어, 1차 기능명세의 화면을 그릴 부품이 갖춰졌습니다. 처음 대조할 때는 1·2차 17종으로 약 절반만 그릴 수 있었습니다.
- 더 필요했던 부품은 약 37종이었습니다. 12.1(공통 13종)을 먼저 만들면 모든 화면의 뼈대를 그릴 수 있습니다.
- 12.4의 광고 미리보기와 소재 한 쌍은 AdFlow만의 부품이라 가장 손이 많이 갑니다. 실험 화면 시안을 그리기 전에 만들어야 합니다.
- 소셜 로그인 버튼은 카카오, 구글, 페이스북이 정한 모양을 따라야 해서 우리 디자인 시스템 밖의 규칙이 섞입니다.
