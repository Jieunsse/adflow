# AdFlow 첫 화면(소개 페이지) 기획 초안

작성일: 2026-11-11 · 상태: 초안 (확정 전)
근거 문서: 기획서(`PRD-adflow.md`), 디자인 설계(`Design-adflow.md`), 디자인 시스템(`DesignSystem-adflow.md`), 이름(`Naming-adflow.md`), 회사 설계 1절 사업 구조와 5절 영업(`docs/company/01`, `05`)
참고한 페이지: 하이웍스 그룹웨어 소개 페이지 (https://biz-solution.hiworks.com/product/groupware, 2026-11-11 확인). 처음에는 포트원 첫 화면을 참고했습니다

상태 표기는 정책서 0.2절과 같습니다. 확정은 정한 것, 권장은 제안하는 안, 미결정은 사용자가 정해야 하는 것입니다.

## 1. 이 페이지가 하는 일

지금은 `/`에 들어오면 로그인 화면으로 바로 넘어갑니다 (`apps/web/app/page.tsx`). 회사와 제품을 소개하는 화면이 없습니다.

이 페이지의 목표는 하나입니다. **대행을 맡기고 싶은 브랜드 대표가 무료 광고 계정 진단을 신청하게 만드는 것입니다.**

| 항목 | 내용 | 상태 |
|---|---|---|
| 첫 번째 목표 | 무료 진단 신청 (영업 문서 2절의 "문의" 단계) | 권장 |
| 두 번째 목표 | 받는 기준에 못 미치는 사람은 개인 구독 출시 알림을 신청하게 합니다 | 권장 |
| 주로 보는 사람 | 자사몰이 있고 월 광고비를 100만 원 이상 쓰는 브랜드 대표 (기획서 4절) | 확정 |
| 주로 들어오는 길 | 우리 Meta 광고, 실험 공개 글 (영업 문서 3절) | 확정 |
| 성공 기준 | 매달 문의 14건 (영업 문서 7절) | 권장 |

- 직원과 대행 고객은 이 페이지를 거의 보지 않습니다. 로그인한 사람은 지금처럼 바로 작업 화면으로 보냅니다 (권장).

## 2. 하이웍스 그룹웨어 소개 페이지에서 가져올 것

2026-11-11에 참고 페이지를 포트원에서 하이웍스로 바꿨습니다 (확정). 포트원 구성은 글이 많고 카드가 작아서, 제품을 실제로 어떻게 쓰는지 보이지 않았습니다. 하이웍스는 실제 제품 화면을 크게 보여 주고, 화면 사이를 점선으로 이어 일의 흐름을 그림으로 보여 줍니다.

하이웍스 페이지는 위에서 아래로 아래 순서입니다.

| 순서 | 하이웍스 | 하는 일 | AdFlow에 가져오는가 |
|---|---|---|---|
| 1 | 위쪽 메뉴와 상담 버튼 | 어디서든 문의할 수 있게 합니다 | 가져옵니다 (3.1) |
| 2 | 가운데 큰 문장, 버튼 2개, 그 아래 제품 화면 모음 | 무슨 제품인지 화면으로 바로 보여 줍니다 | 가져옵니다 (3.2) |
| 3 | 수상, 점유율 같은 숫자 3개 | 믿을 만한 회사라고 말합니다 | 지금은 못 합니다. 진짜 숫자가 없습니다 (4절) |
| 4 | "업무 효율이 떨어지는 이유" 고민 카드 5장이 옆으로 흐름 | 읽는 사람이 자기 문제를 알아보게 합니다 | 가져옵니다 (3.3) |
| 5 | "이렇게 해결합니다" Solution 01~04 | 고민마다 해결하는 기능을 실제 화면으로 보여 줍니다 | 가져옵니다 (3.4) |
| 6 | 각 Solution 아래 고객 한마디 | 실제 사용 결과를 보여 줍니다 | 공개한 실험으로 바꿉니다 (3.5) |
| 7 | 함께 이용하면 좋을 서비스 | 다른 상품을 알려 줍니다 | 상품과 가격으로 바꿉니다 (3.6) |
| 8 | 활용 팁 글 목록 | 읽을거리로 믿음을 줍니다 | 지금은 하지 않습니다. 공개한 실험 글이 그 자리를 대신합니다 |
| 9 | 도입 상담 안내 | 도입 과정을 함께한다고 말합니다 | 시작 과정으로 바꿉니다 (3.7) |
| 10 | 자주 묻는 질문 | 신청 전에 걸리는 점을 풀어 줍니다 | 가져옵니다 (3.8) |
| 11 | 마지막 문장과 버튼 2개 | 끝까지 읽은 사람을 놓치지 않습니다 | 가져옵니다 (3.9) |
| 12 | 아래쪽 회사 정보와 약관 | 법으로 필요한 정보입니다 | 가져옵니다 (3.10) |

하이웍스에서 배울 점은 네 가지입니다.

1. 첫 화면에 실제 제품 화면을 크게 둡니다. 화면 둘레에 알림 카드를 띄우고 점선으로 이어서, 한 번의 요청이 어떻게 끝나는지 한 장으로 보여 줍니다.
2. 고민을 먼저 말하고, 같은 순서로 해결을 보여 줍니다. 고민 카드와 Solution이 짝을 이룹니다.
3. Solution 하나는 제목 한 줄, 설명 두 줄, 기능 탭, 큰 화면, 화면 아래 설명 두 줄로 같은 모양입니다. 모양이 같아서 넘겨 보기 쉽습니다.
4. 화면 위에서 중요한 곳을 테두리로 짚고, 그 부분을 크게 꺼낸 카드를 점선으로 잇습니다. 화면이 작아도 무엇을 봐야 하는지 알 수 있습니다.

## 3. AdFlow 첫 화면 구성

위에서 아래로 이 순서입니다. 문구는 모두 초안입니다.

### 3.1 위쪽 메뉴

| 자리 | 내용 | 상태 |
|---|---|---|
| 왼쪽 | 로고 (이름 확정 전에는 글자로 "AdFlow") | 권장 |
| 가운데 | 대행, 구독, 실험 공개, 가격 | 권장 |
| 오른쪽 | 로그인 (작은 글자 링크), 무료 진단 신청 (진한 버튼) | 권장 |

- 스크롤해도 위쪽 메뉴는 따라옵니다. 그래서 어디서든 진단 신청을 누를 수 있습니다 (권장).
- 휴대폰에서는 가운데 메뉴를 접고, 무료 진단 신청 버튼만 남깁니다 (권장).


### 3.2 첫 화면

하이웍스처럼 문장과 버튼을 가운데에 두고, 그 아래에 제품 화면 모음을 크게 둡니다.

| 자리 | 문구 초안 | 상태 |
|---|---|---|
| 작은 윗줄 | 매주 실험하고 기록으로 남기는 광고 대행 | 권장 |
| 큰 문장 | 이름이 확정된 뒤에 이름과 묶어 정합니다. 시안에는 "광고비를 쓸 때마다, 회사에 배운 것이 남습니다"를 임시로 넣습니다 | 확정 (2026-11-11) |
| 진한 버튼 | 무료 진단 신청하기 | 권장 |
| 옅은 버튼 | 가격 보기 (3.6으로 내려갑니다) | 권장 |
| 버튼 아래 작은 글씨 | 지난 광고를 보고 첫 달 실험 3개를 제안해요. 계약하지 않아도 진단서는 가져가세요. | 권장 |

- 임시 문장은 기획서 5절의 대표용 한 문장입니다. 다른 대행사는 "매출을 올려 드립니다"라고 말합니다. 우리는 "남는다"를 말해야 차이가 보입니다. 이름과 묶은 문장을 만들 때도 이 뜻은 지킵니다.

**제품 화면 모음 (권장).** 실험 하나가 기록이 되기까지를 한 장으로 보여 줍니다.

| 자리 | 내용 | 가져오는 시안 |
|---|---|---|
| 가운데 큰 화면 | 고객이 보는 "이번 달" 화면 | 고객 · 11-1 이번 달 |
| 왼쪽 위 카드 | "월초 계획 승인 요청: 11월 실험 3개, 예산 상한 300만 원" | 고객 · 12-3 계획 승인 |
| 왼쪽 아래 카드 | 두 소재 썸네일과 "같은 예산으로 맞붙이는 중" | 직원 · 2-1 소재 나란히 보기 |
| 오른쪽 위 카드 | "판정 완료: 소재 B 3초 시청률 24.6% (+6.4%p)" | 직원 · 3-1 실험 상세 · 판정 완료 |
| 오른쪽 아래 카드 | 배운 것 기록 한 장. "이 브랜드는 첫 장면에서 쓰는 모습을 보여 줄 때 더 오래 봅니다" | 고객 · 4 배운 것 |

- 카드는 승인 → 시험 → 판정 → 기록 순서로 점선을 잇습니다. 마지막 기록 카드에서 가운데 화면으로 점선이 돌아옵니다. "모든 광고가 다음 광고를 더 낫게 만든다"는 비전을 그림으로 보여 주는 자리입니다.
- 배경은 옅은 격자와 옅은 아이콘만 둡니다. 움직이는 색 배경은 쓰지 않습니다. 디자인 설계 4.3의 "화려하고 과장된 느낌을 피한다"와 맞지 않습니다.
- 하이웍스는 AI에게 말을 거는 말풍선을 넣었습니다. 우리는 넣지 않습니다. "AI가 알아서 다 해 준다"는 느낌은 브랜드 핵심의 "피할 것"입니다 (디자인 설계 4.3).
- 화면 속 숫자는 3.5에 공개한 실험과 같은 숫자만 씁니다. 지어낸 숫자를 쓰지 않습니다 (디자인 원칙 2).
- 휴대폰에서는 가운데 화면 하나와 판정 카드, 기록 카드만 남깁니다.

### 3.3 광고비는 나가는데, 남는 게 없다면

하이웍스의 "업무 효율이 떨어지는 이유" 자리입니다. 대표가 지금 불편한 점을 카드 5장으로 보여 줍니다. 카드는 제목 한 줄과 설명 두 줄입니다.

| 카드 | 제목 | 설명 | 이어지는 해결 |
|---|---|---|---|
| 1 | 광고비는 매달 나가는데, 무엇이 남았는지 모르겠어요 | 소재를 여러 개 바꿔 봤지만, 어떤 것이 왜 잘 됐는지는 기록이 없어요. | 3.4의 03 |
| 2 | 대행사가 "잘 됐어요"라고만 해요 | 왜 잘 됐는지 물어보면 설명이 없어서, 다음 달에도 같은 것을 다시 시도해요. | 3.4의 01 |
| 3 | 담당자가 바뀌면 처음부터 다시 시작해요 | 지난 실험과 결과가 담당자 머릿속에만 있어서, 새 담당자가 같은 실수를 반복해요. | 3.4의 03 |
| 4 | 며칠 만에 결론을 내려요 | 숫자가 충분히 모이기 전에 이긴 쪽을 정해서, 다음 달에 결과가 뒤집혀요. | 3.4의 02 |
| 5 | 광고비가 얼마나 나갔는지 나중에 알아요 | 하루 광고비가 갑자기 늘어도, 월말 리포트를 보고서야 알게 돼요. | 3.4의 04 |

- 근거는 기획서 5절의 대표 "지금" 항목입니다 (권장).
- 데스크톱에서는 카드가 옆으로 천천히 흐릅니다. 하이웍스와 같습니다. 움직임을 줄이도록 설정한 사람에게는 멈춘 채로 보여 줍니다 (권장).

### 3.4 AdFlow가 이렇게 해결해요

하이웍스의 "Solution 01~04" 자리입니다. 기존의 "이렇게 일해요"(4단계)와 "다른 대행사와 다른 점"(4가지)을 여기로 합쳤습니다. 4단계 흐름과 다른 점이 같은 이야기를 두 번 하고 있었기 때문입니다.

Solution 하나는 모두 같은 모양입니다.

1. 번호 표 (Solution 01)
2. 제목 한 줄
3. 설명 두 줄
4. 기능 탭 2~3개. 누르면 아래 화면이 바뀝니다
5. 큰 화면. 실제 시안을 그대로 넣고, 중요한 곳을 테두리로 짚고, 그 부분을 크게 꺼낸 카드를 점선으로 잇습니다
6. 화면 아래 설명 두 줄 (탭마다 다릅니다)

| 번호 | 제목 | 설명 두 줄 | 탭 → 넣는 시안 | 근거 |
|---|---|---|---|---|
| 01 | 실험마다 바꾸는 것은 하나뿐이에요 | 가설 하나를 정하고 같은 예산으로 두 소재를 맞붙여요. 하나만 바꿔야 이긴 이유를 말할 수 있어요. | 실험 만들기 → 직원 · 1-1 실험 만들기 / 소재 나란히 보기 → 직원 · 2-1 소재 나란히 보기 | 기획서 6.1 |
| 02 | 숫자가 모이기 전에는 결론을 내지 않아요 | 정해 둔 노출 수가 모일 때까지 이기고 있는 쪽을 보여 주지 않아요. 판정은 실제 숫자와 정해진 규칙으로만 내요. | 진행 중 → 고객 · 11-2 진행 중 실험 / 판정 완료 → 직원 · 3-1 실험 상세 · 판정 완료 | 기획서 6.2의 6번, 디자인 원칙 4 |
| 03 | 배운 것은 회사에 남아요 | 이긴 이유를 문장으로 기록하고, 다음 소재를 만들 때 먼저 꺼내 봐요. 계약이 끝나도 기록은 가져가세요. | 배운 것 기록 → 고객 · 4 배운 것 / 월간 리포트 → 고객 · 6-1 리포트 | 기획서 2절 "고객사가 소유하는 자산" |
| 04 | 돈이 나가기 전에 물어봐요 | 월초에 그달 계획과 예산 상한을 승인받아요. 하루 광고비가 평소의 2배를 넘으면 멈추고 알려요. | 계획 승인 → 고객 · 12-3 계획 승인 / 예산 상한 멈춤 → 상태 · 실험 상세 · 예산 상한으로 자동 멈춤 | 기획서 6.2의 12·13번 |

화면 아래 설명 두 줄 초안입니다.

| 탭 | 설명 |
|---|---|
| 실험 만들기 | 가설, 바꾸는 것 하나, 판정 기준을 먼저 적어요. 적지 않으면 실험을 시작할 수 없어요. |
| 소재 나란히 보기 | 두 소재를 나란히 놓고 다른 점이 하나인지 확인해요. 둘 이상 다르면 다시 만들어요. |
| 진행 중 | 판정까지 노출이 얼마나 남았는지만 보여 드려요. 중간 숫자로 마음을 바꾸지 않아요. |
| 판정 완료 | 이긴 소재와 숫자 차이, 판정에 쓴 규칙을 한 화면에서 확인해요. |
| 배운 것 기록 | 실험마다 배운 것 한 문장이 쌓여요. 고객 화면에서 언제든 다시 볼 수 있어요. |
| 월간 리포트 | 리포트의 숫자는 AI가 쓰지 않아요. 실제 숫자와 정해진 규칙으로만 만들어요. |
| 계획 승인 | 그달 실험과 예산 상한을 보고 승인해요. 승인 전에는 광고비가 나가지 않아요. |
| 예산 상한 멈춤 | 정한 상한을 넘으려 하면 광고를 멈추고 바로 알려 드려요. |

- 01~03 아래에는 3.5의 공개 실험 한 줄을 하이웍스의 "고객 한마디" 자리에 넣습니다. 예: "처음 3초에 사용 장면을 보여 주니 3초 시청률이 6.4%p 올랐어요. 실험 전체 보기" (권장).
- "기록은 회사 것이에요"는 계약 조건과 맞는지 법·행정 단계에서 확인합니다 (미결정).
- 휴대폰에서는 탭을 옆으로 밀어 넘기고, 화면은 중요한 부분만 잘라 보여 줍니다. 점선과 꺼낸 카드는 빼고, 테두리만 남깁니다 (권장).

### 3.5 이번 주 공개한 실험

하이웍스의 "도입 사례" 자리입니다. 진짜 실험 한 편을 그대로 보여 줍니다. 3.4의 Solution 아래 한 줄도 여기서 가져옵니다.

| 카드에 담는 것 | 예시 |
|---|---|
| 브랜드 | 뷰티 자사몰 A (이름은 빼고 씁니다) |
| 가설 | 처음 3초에 가격보다 사용 장면을 보여 주면 3초 시청률이 오른다 |
| 두 소재 | 소재 A와 소재 B 이미지 |
| 결과 | 3초 시청률 18.2% 대 24.6% (+6.4%p) |
| 배운 것 | 이 브랜드는 첫 장면에서 쓰는 모습을 보여 줄 때 더 오래 봅니다 |
| 버튼 | 실험 전체 보기 (블로그 원문으로 이동) |

- 위 숫자는 예시입니다. 실제 페이지에는 실제로 공개한 실험만 넣습니다 (확정, 영업 문서 3.1).
- 광고비와 매출 금액은 넣지 않고 비율만 넣습니다 (영업 문서 3.1).
- 고객이 생기기 전에는 우리 Meta 광고의 실험을 넣습니다 (영업 문서 3.2).
- 공개한 실험이 3편 이상 모이면 카드를 옆으로 넘겨 볼 수 있게 합니다 (권장).

### 3.6 맡기거나, 직접 하거나

하이웍스의 "함께 이용하면 좋을 서비스" 자리입니다. 사업 구조 문서 3절의 상품과 가격을 한 곳에서 보여 줍니다.

| 카드 | 한 문장 | 가격 (부가세 별도) | 표시 | 버튼 | 상태 |
|---|---|---|---|---|---|
| 대행 | AdFlow로 일하는 우리 팀이 실험을 맡아요 | 라이트 월 59만 원 (월 광고비 300만 원 이하), 스탠다드 월 99만 원 (300만~1,000만 원) | 지금 신청 가능 | 무료 진단 신청하기 | 권장 |
| 개인 구독 | 혼자 광고하는 사장님이 직접 실험해요 | 출시 때 공개 | 곧 열림 | 출시 알림 받기 | 권장 |
| 팀 구독 | 마케팅 팀이 함께 실험하고 기록을 나눠요 | 출시 때 공개 | 곧 열림 | 출시 알림 받기 | 권장 |
| 설치형 | 우리 회사 서버에 AdFlow를 설치해요 | 문의 시 | 문의 시 | 문의하기 | 권장 |

- 대행 카드를 가장 크게 둡니다. 지금 팔 수 있는 상품은 대행 하나이기 때문입니다 (권장).
- 대행 카드 아래에 "첫 달 50% 할인, 계약 기간 3개월"을 적습니다.
- **가격을 첫 화면에 보여 줍니다 (확정, 2026-11-11).** 우리는 고객마다 가격을 깎지 않으므로 숨길 이유가 없습니다 (영업 문서 6절). 가격을 먼저 보면 맞지 않는 문의가 줄어 진단 시간을 아낍니다.
- 다른 광고대행사는 받지 않습니다 (기획서 4절). 페이지에 따로 적지는 않고, 문의 양식에서 업종을 보고 거릅니다 (권장).

### 3.7 시작은 이렇게 해요

하이웍스의 "도입 상담 안내" 자리입니다. 영업 문서 2절의 단계를 고객 입장에서 보여 주고, 받는 기준을 함께 둡니다.

| 단계 | 고객이 하는 일 | 걸리는 시간 |
|---|---|---|
| 1. 신청 | 양식을 채워요 | 2분 |
| 2. 계정 공유 | 광고 계정을 읽기 권한으로 공유해요 | 10분 |
| 3. 진단서 받기 | 지난 광고에서 이긴 것과 진 것, 첫 달 실험 3개를 한 장으로 받아요 | 계정 공유 후 3영업일 |
| 4. 30분 통화 | 진단서 설명을 듣고 맡길지 정해요 | 30분 |

- **진단서는 계정 공유를 받은 날부터 3영업일 안에 드립니다 (확정, 2026-11-11).** 진단 1건이 1시간이면(영업 문서 5절) 대표 혼자서도 지킬 수 있습니다.

단계 옆에 "이런 브랜드와 함께해요" 상자를 둡니다 (영업 문서 4절의 받는 기준). 맞지 않는 사람이 신청하지 않게 미리 보여 줍니다.

- 자사몰이 있어요
- Meta 광고 계정이 있어요
- 월 광고비를 100만 원 이상 쓸 수 있어요
- 제품 사진과 영상을 줄 수 있어요

상자 아래에 작은 글씨로 "아직 광고비가 적다면 개인 구독이 맞아요. 출시되면 알려 드릴게요."와 출시 알림 링크를 둡니다 (권장).

## 6. 진단 신청 양식

첫 화면의 "무료 진단 신청하기" 버튼이 여는 화면입니다. 버튼을 누르면 `/diagnosis` 페이지로 갑니다. Meta 광고의 도착 페이지도 여기입니다 (영업 문서 3.2).

| 칸 | 필수 | 이유 |
|---|---|---|
| 이름 | 예 | 연락 |
| 연락처 (휴대폰) | 예 | 카카오톡으로 연락하기 위해서입니다 |
| 브랜드 이름 | 예 | 영업 기록 |
| 이메일 | 예 | 진단서를 보내고, 계약하면 고객 화면 초대에 씁니다 (정책서 3.1의 초대 이메일) |
| 월 광고비 | 예 | 고르기: 100만 원 미만, 100~300만 원, 300~1,000만 원, 1,000만 원 이상 |
| Meta 광고를 해 본 적 있나요 | 예 | 받는 기준 확인 |
| 하고 싶은 말 | 아니요 | |
| 개인정보 수집 동의 | 예 | 법으로 필요합니다 |

- 시안은 피그마 Main Design 페이지의 "진단 신청 · 휴대폰 375", "진단 신청 · 데스크톱 1440"에 있습니다. 신청 완료 화면은 두 가지입니다. 기준을 채운 경우는 "신청 완료 · 휴대폰 375"이고, 월 광고비 100만 원 미만을 고른 경우는 "신청 완료 · 광고비 100만 원 미만 · 휴대폰 375"입니다 (2026-11-11).
- 동의 칸 아래 문구 "상담이 끝나고 1년 뒤 지워요"는 시안에 임시로 넣은 기간입니다. 실제 보관 기간은 개인정보 처리방침과 함께 정합니다 (미결정).
- 자사몰 주소는 묻지 않습니다 (확정, 2026-11-11). 자사몰이 있는지와 업종은 첫 연락 때 확인합니다 (영업 문서 4절의 받는 기준).
- 칸은 이 8개보다 늘리지 않습니다. 칸이 많을수록 신청이 줄어듭니다 (권장).
- 월 광고비에서 "100만 원 미만"을 고르면 제출 뒤에 개인 구독 출시 알림을 안내합니다 (권장, 영업 문서 4절).
- 들어온 주소의 광고 추적 값(`utm_source` 등)을 함께 저장합니다. 영업 문서 8절의 "문의 경로" 숫자를 따로 묻지 않고 얻기 위해서입니다 (권장).
- **신청이 들어오면 대표에게 알림만 보냅니다 (확정, 2026-11-11).** 대표가 알림을 보고 고객사 "문의" 상태로 직접 등록합니다. 영업 문서 9절이 자동 등록을 1차에서 미뤘기 때문입니다. 알림을 메일로 받을지 카카오톡으로 받을지는 만들 때 정합니다. 손으로 등록하는 일이 많아지면 자동 등록을 당깁니다.
