# AdFlow 첫 화면(소개 페이지) 기획 초안

작성일: 2026-11-11 · 상태: 초안 (확정 전)
근거 문서: 기획서(`PRD-adflow.md`), 디자인 설계(`Design-adflow.md`), 디자인 시스템(`DesignSystem-adflow.md`), 이름(`Naming-adflow.md`), 회사 설계 1절 사업 구조와 5절 영업(`docs/company/01`, `05`)
참고한 페이지: 포트원 첫 화면 (https://www.portone.io/, 2026-11-11 확인)

상태 표기는 정책서 0.2절과 같습니다. 확정은 정한 것, 권장은 제안하는 안, 미결정은 사용자가 정해야 하는 것입니다.

## 1. 이 페이지가 하는 일

지금은 `/`에 들어오면 로그인 화면으로 바로 넘어갑니다 (`apps/web/app/page.tsx`). 회사와 제품을 소개하는 화면이 없습니다.

이 페이지의 목표는 하나입니다. **대행을 맡기고 싶은 브랜드 대표가 무료 광고 계정 진단을 신청하게 만드는 것입니다.**

| 항목 | 내용 | 상태 |
|---|---|---|
| 첫 번째 목표 | 무료 진단 신청 (영업 문서 2절의 "문의" 단계) | 권장 |
| 두 번째 목표 | 받는 기준에 못 미치는 사람은 개인 구독 출시 알림을 신청하게 합니다 | 권장 |
| 주로 보는 사람 | 자사몰이 있고 월 광고비를 100만 원 이상 쓰는 브랜드 대표 (기획서 4절) | 확정 |
| 주로 들어오는 길 | 우리 Meta 광고, 실험 공개 글 (영업 문서 3절) | 확정 |
| 성공 기준 | 매달 문의 14건 (영업 문서 7절) | 권장 |

- 직원과 대행 고객은 이 페이지를 거의 보지 않습니다. 로그인한 사람은 지금처럼 바로 작업 화면으로 보냅니다 (권장).

## 2. 포트원 첫 화면에서 가져올 것

포트원 첫 화면은 위에서 아래로 아래 순서입니다.

| 순서 | 포트원 | 하는 일 | AdFlow에 가져오는가 |
|---|---|---|---|
| 1 | 위쪽 메뉴: 제품, 가격 안내, 리소스, 로그인, 도입 문의 버튼 | 어디서든 문의 버튼을 누를 수 있게 합니다 | 가져옵니다 |
| 2 | 큰 문장 하나, 설명 한 줄, 버튼 하나 | 3초 안에 무슨 회사인지 알게 합니다 | 가져옵니다 |
| 3 | 고객사 로고 띠 | 이미 쓰는 회사가 있다는 믿음을 줍니다 | 지금은 못 합니다. 고객이 없습니다 (4절) |
| 4 | 숫자 4개 (누적 거래액, 고객사 수 등) | 규모를 보여 줍니다 | 지금은 못 합니다. 진짜 숫자가 없습니다 (4절) |
| 5 | 제품 카드. 일부는 "곧 열림" 표시 | 지금 살 수 있는 것과 앞으로 나올 것을 함께 보여 줍니다 | 가져옵니다 |
| 6 | 제품별 고객 한마디 | 실제 사용 결과를 보여 줍니다 | 실험 공개로 바꿉니다 (4절) |
| 7 | 왜 우리인가 4가지 | 경쟁사와 다른 점을 말합니다 | 가져옵니다 |
| 8 | 연결되는 시스템 | 지금 쓰는 도구 그대로 쓸 수 있다고 말합니다 | 시작 과정으로 바꿉니다 |
| 9 | 보안 인증 | 맡겨도 안전하다고 말합니다 | 권한과 데이터 약속으로 바꿉니다 |
| 10 | 마지막 문의 버튼 | 끝까지 읽은 사람을 놓치지 않습니다 | 가져옵니다 |
| 11 | 아래쪽: 제품 목록, 사이트 맵, 회사 정보, 약관 | 법으로 필요한 정보와 길 찾기 | 가져옵니다 |

포트원에서 배울 점은 세 가지입니다.

1. 버튼은 "도입 문의" 하나뿐입니다. 위쪽 메뉴, 첫 화면, 맨 아래가 모두 같은 버튼입니다. 읽는 사람이 무엇을 눌러야 할지 고민하지 않습니다.
2. 제품마다 "무엇을, 어떻게" 한 문장씩만 씁니다. 자세한 설명은 제품 페이지로 넘깁니다.
3. 아직 없는 제품도 "곧 열림"으로 보여 줍니다. 회사가 어디로 가는지 알 수 있습니다.

## 3. AdFlow 첫 화면 구성

위에서 아래로 이 순서입니다. 문구는 모두 초안입니다.

### 3.1 위쪽 메뉴

| 자리 | 내용 | 상태 |
|---|---|---|
| 왼쪽 | 로고 (이름 확정 전에는 글자로 "AdFlow") | 권장 |
| 가운데 | 대행, 구독, 실험 공개, 가격 | 권장 |
| 오른쪽 | 로그인 (작은 글자 링크), 무료 진단 신청 (진한 버튼) | 권장 |

- 스크롤해도 위쪽 메뉴는 따라옵니다. 그래서 어디서든 진단 신청을 누를 수 있습니다 (권장).
- 휴대폰에서는 가운데 메뉴를 접고, 무료 진단 신청 버튼만 남깁니다 (권장).

### 3.2 첫 화면

| 자리 | 문구 초안 | 상태 |
|---|---|---|
| 큰 문장 | 이름이 확정된 뒤에 이름과 묶어 정합니다. 시안에는 "광고비를 쓸 때마다, 회사에 배운 것이 남습니다"를 임시로 넣습니다 | 확정 (2026-11-11) |
| 설명 | 매주 실험하고, 무엇이 왜 이겼는지 기록으로 드려요. 담당자가 바뀌어도 기록은 회사에 남아요. | 권장 |
| 버튼 | 무료 진단 신청하기 | 권장 |
| 버튼 아래 작은 글씨 | 지난 광고를 보고 첫 달 실험 3개를 제안해요. 계약하지 않아도 진단서는 가져가세요. | 권장 |

- 임시 문장은 기획서 5절의 대표용 한 문장입니다. 다른 대행사는 "매출을 올려 드립니다"라고 말합니다. 우리는 "남는다"를 말해야 차이가 보입니다. 이름과 묶은 문장을 만들 때도 이 뜻은 지킵니다.
- 오른쪽이나 아래에는 실제 제품 화면 한 장을 둡니다. "배운 것 기록" 카드 하나가 가장 좋습니다. 가설, 두 소재, 이긴 쪽, 배운 것이 한 장에 보이기 때문입니다 (권장).
- 포트원처럼 움직이는 색 배경은 쓰지 않습니다. 디자인 설계 4.3의 "화려하고 과장된 느낌을 피한다"와 맞지 않습니다 (권장).

### 3.3 이런 고민이 있나요

포트원의 "고객사 로고 띠" 자리입니다. 고객이 생기기 전에는 대표가 지금 겪는 문제로 시작합니다.

| 카드 | 문구 초안 |
|---|---|
| 1 | 광고비는 매달 나가는데, 무엇이 남았는지 모르겠어요 |
| 2 | 담당자가 바뀌면 처음부터 다시 시작해요 |
| 3 | 대행사가 "이게 잘 됐어요"라고만 하고, 왜 잘 됐는지는 말해 주지 않아요 |

- 근거는 기획서 5절의 대표 "지금" 항목입니다 (권장).

### 3.4 AdFlow는 이렇게 일해요

기획서 6.1의 핵심 흐름을 4단계로 줄여 보여 줍니다.

| 단계 | 제목 | 한 문장 |
|---|---|---|
| 1 | 가설 하나 | 실험마다 바꾸는 것은 하나뿐이에요. 그래야 이긴 이유를 말할 수 있어요. |
| 2 | 두 소재로 시험 | 같은 예산으로 두 소재를 맞붙여요. |
| 3 | 숫자로 판정 | 정해 둔 노출 수가 모이기 전에는 결론을 내지 않아요. |
| 4 | 배운 것 기록 | 이긴 이유를 문장으로 남기고, 다음 소재에 써요. |

- 4단계 오른쪽에서 1단계로 돌아오는 화살표를 그립니다. "모든 광고가 다음 광고를 더 낫게 만든다"는 비전을 그림으로 보여 주는 자리입니다 (권장).

### 3.5 이번 주 공개한 실험

포트원의 "숫자 4개"와 "고객 한마디" 자리입니다. 진짜 실험 한 편을 그대로 보여 줍니다.

| 카드에 담는 것 | 예시 |
|---|---|
| 브랜드 | 뷰티 자사몰 A (이름은 빼고 씁니다) |
| 가설 | 처음 3초에 가격보다 사용 장면을 보여 주면 3초 시청률이 오른다 |
| 두 소재 | 소재 A와 소재 B 이미지 |
| 결과 | 3초 시청률 18.2% 대 24.6% (+6.4%p) |
| 배운 것 | 이 브랜드는 첫 장면에서 쓰는 모습을 보여 줄 때 더 오래 봅니다 |
| 버튼 | 실험 전체 보기 (블로그 원문으로 이동) |

- 위 숫자는 예시입니다. 실제 페이지에는 실제로 공개한 실험만 넣습니다 (확정, 영업 문서 3.1).
- 광고비와 매출 금액은 넣지 않고 비율만 넣습니다 (영업 문서 3.1).
- 고객이 생기기 전에는 우리 Meta 광고의 실험을 넣습니다 (영업 문서 3.2).
- 공개한 실험이 3편 이상 모이면 카드를 옆으로 넘겨 볼 수 있게 합니다 (권장).

### 3.6 맡기거나, 직접 하거나

포트원의 "제품 카드" 자리입니다. 사업 구조 문서 3절의 상품을 그대로 보여 줍니다.

| 카드 | 한 문장 | 표시 | 버튼 | 상태 |
|---|---|---|---|---|
| 대행 | AdFlow로 일하는 우리 팀이 실험을 맡아요 | 지금 신청 가능 | 무료 진단 신청하기 | 권장 |
| 개인 구독 | 혼자 광고하는 사장님이 직접 실험해요 | 곧 열림 | 출시 알림 받기 | 권장 |
| 팀 구독 | 마케팅 팀이 함께 실험하고 기록을 나눠요 | 곧 열림 | 출시 알림 받기 | 권장 |
| 설치형 | 우리 회사 서버에 AdFlow를 설치해요 | 문의 시 | 문의하기 | 권장 |

- 대행 카드를 가장 크게 둡니다. 지금 팔 수 있는 상품은 대행 하나이기 때문입니다 (권장).
- 다른 광고대행사는 받지 않습니다 (기획서 4절). 페이지에 따로 적지는 않고, 문의 양식에서 업종을 보고 거릅니다 (권장).

### 3.7 다른 대행사와 다른 점

포트원의 "왜 우리인가 4가지" 자리입니다.

| 제목 | 한 문장 | 근거 |
|---|---|---|
| 이유까지 드려요 | 결과만 말하지 않고, 무엇을 바꿔서 이겼는지 기록으로 드려요 | 기획서 2절 |
| 기록은 회사 것이에요 | 계약이 끝나도 배운 것 기록은 가져가세요 | 기획서 2절 "고객사가 소유하는 자산" |
| 숫자로만 말해요 | 성과 리포트의 숫자는 AI가 쓰지 않아요. 실제 숫자와 정해진 규칙으로만 만들어요 | 기획서 6.2의 6번 |
| 돈이 나가기 전에 물어봐요 | 월초에 그달 계획과 예산 상한을 승인받아요. 하루 광고비가 2배를 넘으면 멈추고 알려요 | 기획서 6.2의 12·13번 |

- "기록은 회사 것이에요"는 계약 조건과 맞는지 법·행정 단계에서 확인합니다 (미결정).

### 3.8 시작은 이렇게 해요

포트원의 "연결되는 시스템" 자리입니다. 영업 문서 2절의 단계를 고객 입장에서 보여 줍니다.

| 단계 | 고객이 하는 일 | 걸리는 시간 |
|---|---|---|
| 1. 신청 | 양식을 채워요 | 2분 |
| 2. 계정 공유 | 광고 계정을 읽기 권한으로 공유해요 | 10분 |
| 3. 진단서 받기 | 지난 광고에서 이긴 것과 진 것, 첫 달 실험 3개를 한 장으로 받아요 | 계정 공유 후 3영업일 |
| 4. 30분 통화 | 진단서 설명을 듣고 맡길지 정해요 | 30분 |

- **진단서는 계정 공유를 받은 날부터 3영업일 안에 드립니다 (확정, 2026-11-11).** 영업 문서에 없던 새 약속입니다. 진단 1건이 1시간이면(영업 문서 5절) 대표 혼자서도 지킬 수 있습니다. 영업 문서 5절에도 같은 규칙을 더합니다.

### 3.9 이런 브랜드와 함께해요

영업 문서 4절의 받는 기준입니다. 맞지 않는 사람이 신청하지 않게 미리 보여 줍니다.

- 자사몰이 있어요
- Meta 광고 계정이 있어요
- 월 광고비를 100만 원 이상 쓸 수 있어요
- 제품 사진과 영상을 줄 수 있어요

아래에 작은 글씨로 "아직 광고비가 적다면 개인 구독이 맞아요. 출시되면 알려 드릴게요."와 출시 알림 링크를 둡니다 (권장).

### 3.10 가격

| 상품 | 가격 (부가세 별도) |
|---|---|
| 대행 라이트 (월 광고비 300만 원 이하) | 월 59만 원 |
| 대행 스탠다드 (월 광고비 300만~1,000만 원) | 월 99만 원 |
| 첫 달 | 50% 할인 |
| 계약 기간 | 3개월 |

- **가격을 첫 화면에 보여 줍니다 (확정, 2026-11-11).** 포트원은 가격을 다른 페이지로 넘깁니다. 우리는 고객마다 가격을 깎지 않으므로 숨길 이유가 없습니다 (영업 문서 6절). 가격을 먼저 보면 맞지 않는 문의가 줄어 진단 시간을 아낍니다.
- 구독 가격은 출시 때 넣습니다. 지금은 "곧 열림"만 둡니다 (권장).

### 3.11 권한과 데이터 약속

포트원의 "보안 인증" 자리입니다. 우리는 아직 인증이 없으므로 약속을 씁니다.

- 진단은 읽기 권한으로만 해요. 진단이 끝나면 공유를 해제해도 돼요.
- 공개하는 실험에는 브랜드 이름과 금액을 넣지 않아요. 동의한 고객의 실험만 공개해요.
- 광고 계정은 비밀번호가 아니라 Meta의 파트너 공유로 받아요.

- 첫째 줄은 Meta 문서 확인이 끝나야 쓸 수 있습니다 (영업 문서 10절, 미결정).

### 3.12 마지막 버튼

| 자리 | 문구 초안 |
|---|---|
| 큰 문장 | 내 광고에서 무엇을 배울 수 있는지 먼저 확인해 보세요 |
| 버튼 | 무료 진단 신청하기 |
| 보조 | 카카오톡 채널로 물어보기 |

### 3.13 아래쪽

포트원과 같은 구성입니다. 대행, 구독, 실험 공개, 가격, 이용약관(`/terms`), 개인정보 처리방침(`/privacy`), 회사 정보(상호, 대표, 주소, 사업자등록번호, 통신판매업 신고번호)를 둡니다.

- 회사 정보는 사업자 등록 뒤에 채웁니다 (법·행정 문서, 미결정).

## 4. 지금은 하지 않는 것

| 하지 않는 것 | 이유 | 언제 다시 보는가 |
|---|---|---|
| 고객사 로고 띠 | 고객이 없습니다. 로고를 쓰려면 고객 동의도 필요합니다 | 동의한 대행 고객 3곳 이상 |
| 누적 숫자 (고객 수, 실험 수) | 작은 숫자는 오히려 믿음을 떨어뜨립니다. 지어낸 숫자는 디자인 원칙 2와 맞지 않습니다 | 공개 실험 30편 이상 |
| 고객 한마디 | 받은 말이 없습니다 | 첫 재계약 고객 |
| 움직이는 배경, 숫자가 올라가는 효과 | 브랜드 핵심의 "피할 것"과 맞지 않고, 휴대폰에서 느립니다 | 다시 보지 않음 |
| 상담 채팅 창 | 대표 혼자 응대할 수 없습니다. 카카오톡 채널 링크로 대신합니다 | 대행팀 직원 채용 후 |
| 구독 가입 화면 | 구독은 2차입니다 | 2차 출시 |

## 6. 진단 신청 양식

포트원의 "도입 문의" 버튼이 여는 화면입니다. 버튼을 누르면 `/diagnosis` 페이지로 갑니다. Meta 광고의 도착 페이지도 여기입니다 (영업 문서 3.2).

| 칸 | 필수 | 이유 |
|---|---|---|
| 이름 | 예 | 연락 |
| 연락처 (휴대폰) | 예 | 카카오톡으로 연락하기 위해서입니다 |
| 브랜드 이름 | 예 | 영업 기록 |
| 자사몰 주소 | 예 | 받는 기준 확인. 업종도 여기서 봅니다 |
| 월 광고비 | 예 | 고르기: 100만 원 미만, 100~300만 원, 300~1,000만 원, 1,000만 원 이상 |
| Meta 광고를 해 본 적 있나요 | 예 | 받는 기준 확인 |
| 하고 싶은 말 | 아니요 | |
| 개인정보 수집 동의 | 예 | 법으로 필요합니다 |

- 시안은 피그마 Main Design 페이지의 "진단 신청 · 휴대폰 375", "진단 신청 · 데스크톱 1440"에 있습니다. 신청 완료 화면은 두 가지입니다. 기준을 채운 경우는 "신청 완료 · 휴대폰 375"이고, 월 광고비 100만 원 미만을 고른 경우는 "신청 완료 · 광고비 100만 원 미만 · 휴대폰 375"입니다 (2026-11-11).
- 동의 칸 아래 문구 "상담이 끝나고 1년 뒤 지워요"는 시안에 임시로 넣은 기간입니다. 실제 보관 기간은 개인정보 처리방침과 함께 정합니다 (미결정).
- 칸은 이 8개보다 늘리지 않습니다. 칸이 많을수록 신청이 줄어듭니다 (권장).
- 월 광고비에서 "100만 원 미만"을 고르면 제출 뒤에 개인 구독 출시 알림을 안내합니다 (권장, 영업 문서 4절).
- 들어온 주소의 광고 추적 값(`utm_source` 등)을 함께 저장합니다. 영업 문서 8절의 "문의 경로" 숫자를 따로 묻지 않고 얻기 위해서입니다 (권장).
- **신청이 들어오면 대표에게 알림만 보냅니다 (확정, 2026-11-11).** 대표가 알림을 보고 고객사 "문의" 상태로 직접 등록합니다. 영업 문서 9절이 자동 등록을 1차에서 미뤘기 때문입니다. 알림을 메일로 받을지 카카오톡으로 받을지는 만들 때 정합니다. 손으로 등록하는 일이 많아지면 자동 등록을 당깁니다.
