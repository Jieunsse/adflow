# AdFlow 정책서

기준 문서: `PRD-adflow.md`, `TestScenarios-adflow.md`, `PreMortem-adflow-2026-11-11.md`, `docs/company/01`~`06`
회사 설계 문서 이름: 사업 구조(01), 재무(02), 조직(03), 운영(04), 영업(05), 법·행정(06). 가격과 요금제는 사업 구조 문서 3절을 따릅니다. `BM-adflow.md`는 대체됨입니다.

## 0. 이 문서를 읽는 법

### 0.1 이 문서가 정하는 것

이 문서는 1차~3차 출시에서 서비스가 지킬 규칙을 모두 정합니다.
화면 설계, 개발, 시험 시나리오, 이용약관은 이 문서를 기준으로 만듭니다.
이 문서와 다른 문서가 다르면 이 문서를 따릅니다. 다만 법령과 Meta 정책이 이 문서보다 앞섭니다.

### 0.2 상태 표기

모든 규칙에는 상태를 붙입니다.

| 상태 | 뜻 |
|---|---|
| 확정 | 기획서, 사업 모델 문서, 지금 코드에서 이미 정해진 규칙입니다 |
| 권장 | 이 문서에서 처음 제안하는 규칙입니다. 검토 후 확정합니다 |
| 미결정 | 실험이나 외부 확인을 거쳐야 정할 수 있는 규칙입니다. 정하기 전까지 쓸 임시 값을 함께 적습니다 |
| 법률 검토 | 법령 해석이 필요한 규칙입니다. 공개 전에 변호사 확인을 받습니다 |

### 0.3 "지금 코드" 표기

규칙 표의 "지금 코드" 열은 2026-11-11 기준 코드와 규칙을 비교한 결과입니다.

| 표기 | 뜻 |
|---|---|
| 있음 | 코드가 이미 이 규칙대로 동작합니다 |
| 다름 | 코드가 있지만 규칙과 다르게 동작합니다. 고쳐야 합니다 |
| 없음 | 코드가 없습니다. 새로 만들어야 합니다 |
| 화면만 | 화면에서만 막고 서버에서는 막지 않습니다. 서버 검사를 더해야 합니다 |

고쳐야 할 항목은 25절에 모았습니다.

## 1. 용어

| 용어 | 뜻 |
|---|---|
| 워크스페이스 | 브랜드, 사람, 연결, 기록이 속하는 공간입니다. 두 종류가 있습니다 |
| 회사 워크스페이스 | 우리 회사가 대행에 쓰는 워크스페이스입니다. 하나뿐이고, 대행 고객의 브랜드를 여러 개 둡니다 |
| 고객 워크스페이스 | 구독 고객이 쓰는 워크스페이스입니다 (2차). 브랜드는 1개입니다 |
| 브랜드 | 광고를 내는 상품 묶음입니다. 대행에서는 대행 고객 하나가 브랜드 하나입니다 |
| 고객사 | 회사 워크스페이스에서 영업과 계약을 관리하는 단위입니다. 브랜드 하나와 짝을 이룹니다 (27절) |
| 담당 직원 | 대행 브랜드 하나를 맡은 퍼포먼스 마케터입니다 |
| 월간 계획 | 대행 고객이 매달 승인하는 그달 실험 계획과 총예산 상한입니다 (11.4절) |
| 직접 올리기 모드 | Meta에 자동으로 올리지 않는 방식입니다. AdFlow가 소재와 게재 안내를 만들고, 사용자가 광고관리자에서 직접 올린 뒤 결과 파일을 올립니다 (2차, 4절) |
| 브랜드 프로필 | 브랜드 소개, 말투, 고객 목소리, 근거 자료처럼 소재를 만들 때 쓰는 정보입니다 |
| 브랜드 규칙 | 팀장이 정한 광고 문구 규칙입니다. 금지어, 필수 문구, 글자 수 같은 것입니다. 코드에서는 SOP라고 부릅니다 |
| 목표 | 광고로 이루려는 결과입니다. 예: 30일 동안 링크 클릭 늘리기 |
| 실험 | 가설 하나를 확인하려고 소재 2개를 맞붙이는 일입니다. 코드에서는 토너먼트의 한 라운드입니다 |
| 실험 묶음 | 같은 목표 아래에서 이어서 진행하는 실험들입니다. 코드에서는 토너먼트입니다 |
| 기준 소재 | 지금까지 이긴 소재입니다. 다음 실험에서 도전 소재와 맞붙습니다. 코드에서는 챔피언입니다 |
| 도전 소재 | 기준 소재에서 요소 하나만 바꾼 소재입니다. 코드에서는 챌린저입니다 |
| 바꾸는 요소 | 실험에서 기준 소재와 도전 소재가 다른 부분입니다. 실험마다 하나만 바꿉니다 |
| 가설 | "무엇을 바꾸면 어떤 지표가 어떻게 될 것이다"를 적은 한 문장입니다 |
| 판정 | 실험 결과로 이긴 쪽을 정하는 일입니다 |
| 배운 것 기록 | 판정이 끝난 실험의 바꾼 요소, 수치, 결과를 정리한 기록입니다 |
| 브랜드 지식 | 마케터가 확정한 배운 것 기록입니다. 다음 소재를 만들 때만 브랜드 지식을 씁니다 |
| 과거 기록 | Meta나 엑셀에서 가져온 지난 광고 기록입니다. 브랜드 지식과 따로 둡니다 |
| 오늘의 결정 | 대시보드 맨 위에 보이는, 오늘 사람이 정해야 할 일입니다 |
| 게재 요청 | 소재를 Meta에 올려 달라고 요청하는 일입니다 |
| 게재 승인 | 게재 요청을 사람이 승인하는 일입니다. 승인해야 Meta에 올라갑니다 |
| Meta 검토 | Meta가 광고를 심사하는 일입니다. 게재 승인과 다릅니다 |
| 기본 AI | AdFlow가 비용을 내고 제공하는 AI입니다. 지금은 Gemini입니다 |
| 고객 AI | 고객사가 자기 키로 연결한 AI입니다 |

## 2. 요금제와 이용 범위

사업 구조 문서 3절의 상품을 기능 규칙으로 옮깁니다. 가격과 이유는 사업 구조 문서를 봅니다.

| 항목 | 대행 (1차) | 개인 구독 (2차) | 팀 구독 (3차) | 상태 | 지금 코드 |
|---|---|---|---|---|---|
| 워크스페이스 | 회사 워크스페이스 | 고객 워크스페이스 | 고객 워크스페이스 | 확정 | 없음 |
| 브랜드 수 | 고객사마다 1개. 회사 워크스페이스 전체는 제한 없음 | 1개 | 1개 | 확정 | 다름 (브랜드 프로필 여러 개 가능) |
| 사용자 | 우리 직원, 그리고 고객사마다 "고객" 역할 최대 3명 | 1명 | 최대 5명 | 권장 | 없음 |
| 역할 구분 | 팀장, 팀원·게재, 팀원·검토, 고객 | 없음. 혼자 쓰는 사람이 팀장입니다 | 팀장, 팀원·게재, 팀원·검토 | 확정 | 화면만 |
| Meta 게재 | 자동 (파트너 공유, 4.0절) | 직접 올리기 모드 | 자동. 직접 올리기 모드도 고를 수 있음 | 확정 | 다름 (납품형만) |
| 게재 승인 | 고객의 월간 계획 승인과 담당 직원 승인 (11.4절) | 본인 | 팀장, 팀원·게재 | 확정 | 없음 |
| 월간 리포트 | 고객 화면, 카카오톡 채널로 링크 | 화면에서만 | 이메일, 슬랙. 받는 사람 최대 3명 | 확정 | 없음 |
| 기본 AI 이미지 생성 | 한도 없음 (우리 비용) | 월 50장 | 월 200장 | 권장 | 없음 |
| 쇼츠 렌더링 | 2차부터, 한도 없음 | 월 10개 | 월 40개 | 권장 | 없음 |
| 기본 AI 텍스트 생성 | 한도 없음 | 월 300번 | 월 1,200번 | 권장 | 없음 |
| 고객 AI 연결 | 쓰지 않음 | 가능 | 가능 | 확정 | 없음 |
| 가져오기 | Meta 지난 광고 (엑셀은 2차부터) | Meta 결과 파일, 엑셀 | Meta 지난 광고, 엑셀 | 확정 | 없음 |

- **대행에 한도를 두지 않는 이유 (권장).** 대행의 AI 비용은 우리 운영비입니다. 대신 고객당 AI 비용을 매달 봅니다 (재무 문서 5절).
- **고객 역할을 고객사마다 3명까지로 두는 이유 (권장).** 대표, 실무자, 회계 담당 정도면 충분합니다.

### 2.1 사용 한도 (2차)

| 규칙 | 상태 | 지금 코드 |
|---|---|---|
| 한도는 결제일부터 다음 결제일 전날까지를 한 달로 셉니다 | 권장 | 없음 |
| 다시 만들기도 1번으로 셉니다. 실패한 생성은 세지 않습니다 | 권장 | 없음 |
| 고객 AI로 만든 것은 한도에 세지 않습니다 | 확정 | 없음 |
| 한도의 80%에 닿으면 팀장에게 한 번 알립니다 | 권장 | 없음 |
| 한도에 닿으면 그 기능만 멈춥니다. 실험 판정, 기록, 리포트는 멈추지 않습니다 | 권장 | 없음 |
| 한도를 넘은 사용량에 추가 요금을 받지 않습니다 | 확정 | 없음 |
| 한도에 닿았을 때 문구: "이번 달 이미지 생성 50장을 모두 썼어요. 12월 1일에 다시 쓸 수 있어요. 지금 바로 쓰려면 설정에서 내 AI 키를 연결해 주세요." | 권장 | 없음 |
| 진행 중인 실험의 소재를 만드는 도중 한도에 닿아도, 그 실험에 필요한 나머지 1개는 만들 수 있게 합니다 | 권장 | 없음 |

- **진행 중 실험 예외 (권장).** 소재 하나만 만들어진 상태로 멈추면 실험을 시작할 수 없습니다. 그러면 이미 쓴 한도가 낭비됩니다.

## 3. 계정과 로그인

### 3.1 가입과 로그인

| 규칙 | 상태 | 지금 코드 |
|---|---|---|
| 직원은 Facebook 계정으로 로그인합니다. 광고 계정과 페이지 권한을 같은 로그인에서 받습니다 | 확정 | 있음 |
| 고객 역할은 이메일 가입, 페이스북, 구글, 카카오 중 하나로 로그인합니다. Meta 권한은 받지 않습니다 | 확정 | 없음 |
| 고객은 초대받은 이메일과 로그인 계정의 이메일이 같아야 들어올 수 있습니다. 다르면 연결하지 않고 담당자에게 초대를 다시 요청하라고 안내합니다 | 확정 | 없음 |
| 이메일이 같으면 어떤 로그인 방법으로 들어와도 같은 계정입니다. 설정에서 로그인 방법을 더 연결하거나 끊을 수 있고, 마지막 하나는 끊을 수 없습니다 | 확정 | 없음 |
| 이메일 가입은 인증 메일의 링크를 눌러야 끝납니다. 인증 링크는 24시간 동안 쓸 수 있습니다 | 권장 | 없음 |
| 비밀번호는 8자 이상이고 영문과 숫자를 모두 넣습니다. 서버에는 되돌릴 수 없는 방식(해시)으로만 저장합니다 | 권장 | 없음 |
| 이메일 로그인이 5번 연속 실패하면 15분 동안 막습니다. 문구: "로그인에 여러 번 실패해 15분 동안 막혔어요. 잠시 뒤에 다시 해 주세요." | 권장 | 없음 |
| 비밀번호 재설정 링크는 30분 동안 한 번만 쓸 수 있습니다 | 권장 | 없음 |
| 2차 이후 구독 고객도 같은 네 가지 방법으로 가입합니다. 3차 Meta 자동 연결은 따로 Facebook 연결을 받습니다 | 권장 | 없음 |
| 만 14세 미만은 가입할 수 없습니다. 가입 때 "만 14세 이상이에요"에 동의를 받습니다 | 권장 | 없음 |
| 가입할 때 이용약관과 개인정보처리방침에 각각 동의를 받습니다. 둘 중 하나라도 동의하지 않으면 가입할 수 없습니다 | 권장 | 없음 |
| 마케팅 정보 수신은 따로 고르게 하고, 기본값은 "받지 않음"입니다 | 권장 | 없음 |
| 둘러보기(데모)는 로그인 없이 쓸 수 있습니다. 둘러보기에서는 Meta에 아무것도 올리지 않고 데이터를 저장하지 않습니다 | 확정 | 있음 |

### 3.2 세션

|---|---|---|

## 5. 사람과 역할

### 5.1 역할

역할은 4개입니다. "고객"은 회사 워크스페이스에서만 씁니다. 개인 구독에는 역할 구분이 없고, 혼자 쓰는 사람이 팀장입니다.

| 역할 | 설명 |

| 팀원·검토 | 실험과 소재를 만들고 게재를 요청할 수 있습니다. 승인은 할 수 없습니다 |

### 11.4 대행 게재 승인 (월간 계획)

| 규칙 | 상태 | 지금 코드 |
|---|---|---|

| 고객은 승인하거나, 이유를 적고 반려합니다 | 확정 | 없음 |
| 승인된 계획이 없는 달에는 새 실험을 게재할 수 없습니다. 진행 중 실험은 끝까지 진행합니다 | 확정 | 없음 |
| 승인된 계획 안의 실험은 담당 직원이나 팀장이 게재를 승인합니다. 11.2절의 승인 규칙을 그대로 따릅니다 | 확정 | 없음 |

| 승인 기록(누가, 언제, 어떤 계획과 상한)은 변경 이력에 남기고 고칠 수 없습니다 | 확정 | 없음 |

## 23. 법적 정책

이 절은 서비스가 지켜야 할 법령과 플랫폼 약관을 기능 규칙으로 옮긴 것입니다.
법령 내용은 2026-11-11 기준으로 알고 있는 범위에서 정리했습니다. **공개 전에 반드시 변호사 검토를 받습니다 (법률 검토).**

### 23.1 운영 주체와 계약 구조

| 규칙 | 상태 |
|---|---|
| 서비스 운영 주체(사업자 이름, 대표자, 사업자등록번호, 주소, 연락처)를 이용약관과 화면 아래에 적습니다 | 법률 검토 |
| 개인 구독을 온라인으로 판매하려면 통신판매업 신고를 먼저 합니다. 신고 번호를 화면 아래에 적습니다 | 법률 검토 |
| 대행, 팀 구독, 납품 고객과는 계약서를 따로 씁니다 (법·행정 문서 3절). 이용약관은 계약서에 없는 내용을 채웁니다 | 권장 |
| 대행과 팀 구독 계약에는 개인정보 처리 위탁 계약을 함께 넣습니다 (23.3절) | 법률 검토 |

**누가 개인정보를 책임지는가 (법률 검토).** 기본 운영은 우리가 운영하는 AdFlow 하나입니다 (사업 구조 문서 5절).
- 대행과 팀 구독: 고객사의 직원 정보와 광고 데이터는 고객사가 개인정보처리자이고, AdFlow 운영자는 처리를 맡은 수탁자입니다.
- 개인 구독: AdFlow 운영자가 개인정보처리자입니다.
- 납품: AdFlow를 고객사 서버에 설치하고 운영자가 데이터에 접근하지 않으므로 위탁 관계가 아닙니다.
- 영업 기록(문의한 사람의 연락처, 상담 메모): 우리 회사가 개인정보처리자입니다 (27절, 법·행정 문서 6절).

### 23.5 광고 표현 법규

AdFlow는 고객사 광고를 만드는 도구입니다. 광고 내용의 법적 책임은 광고주인 고객사에 있습니다.
그래도 AdFlow가 만든 문구가 법을 어기면 고객사가 처분을 받고 AdFlow도 신뢰를 잃습니다.
그래서 아래 표현을 업종별 기본 금지어 묶음(7.3절)으로 막습니다.

#### 모든 업종 (표시광고법)

| 막는 표현 | 예 | 상태 |
|---|---|---|
| 근거 없는 최상급, 1등 표현 | "최고", "최초", "1위", "유일", "가장" | 권장 (법률 검토) |
| 근거 없는 숫자 | "만족도 98%", "10만 개 판매" (근거 자료에 출처가 없을 때) | 권장 |
| 경쟁사를 깎아내리는 비교 | "A사 제품보다 낫다" | 권장 (법률 검토) |
| 효과 보장 | "100% 효과", "무조건", "보장" | 권장 (법률 검토) |

- 표시광고법은 광고 속 사실을 광고주가 증명하도록 합니다. 근거 자료(6.1절)에 출처가 있는 숫자와 사실만 쓰게 하는 것이 이 규칙의 바탕입니다.
- 근거 자료에 출처가 있는 최상급 표현("2025년 OO 조사 1위")은 출처를 함께 쓰면 허용합니다 (권장, 법률 검토).

### 23.6 AI 생성물 표시 (AI 기본법)

「인공지능 발전과 신뢰 기반 조성 등에 관한 기본법」(AI 기본법)이 2026년 1월 22일부터 시행됐습니다.
이 법은 생성형 AI로 만든 결과물에 AI로 만들었다는 표시를 하도록 합니다. 실제와 구분하기 어려운 이미지와 영상은 사람이 분명히 알 수 있게 알려야 합니다.
AdFlow는 생성형 AI로 광고 소재를 만들어 고객사에 제공하므로 이 의무가 적용될 수 있습니다 (법률 검토).

| 규칙 | 상태 | 지금 코드 |
|---|---|---|
| 서비스 안에서 AI로 만든 소재에는 "AI 생성" 표시를 붙입니다 | 권장 (법률 검토) | 없음 |
| 가입할 때와 소재를 처음 만들 때 "이 서비스는 생성형 AI로 광고 소재를 만들어요"라고 알립니다 | 권장 (법률 검토) | 없음 |
| AI가 만든 이미지와 쇼츠 파일에 AI 생성 정보를 파일 안에 기록합니다 | 권장 (외부 검증) | 없음 |
| 실제와 구분하기 어려운 이미지(실제 같은 장소, 사물)는 광고에도 "AI로 만든 이미지" 같은 표시를 넣도록 기본값을 켭니다 | 권장 (법률 검토) | 없음 |
| 실제 사람처럼 보이는 인물은 만들지 않습니다 (10.3절) | 권장 | 없음 |
| Meta가 AI 생성물에 붙이는 표시 정책을 따릅니다 | 외부 검증 | 없음 |
| 게재 요청 전 검사에서 AI 생성 표시를 확인합니다 (11.1절 12번) | 권장 (법률 검토) | 없음 |

- 이 법은 위반에 과태료를 정하지만, 정부가 시행 초기에 계도 기간을 두겠다고 밝혔습니다. 계도 기간과 세부 표시 방법은 시행령과 고시를 확인해 정합니다 (외부 검증).
- 광고에 표시를 넣는 기본값은 성과(클릭률)에 영향을 줄 수 있습니다. 그래도 법 위반 가능성이 있는 동안에는 켜 둡니다 (권장).
